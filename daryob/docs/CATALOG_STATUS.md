# Статус каталогов DARYOB

Источник: `assets/catalog/daryob_catalog_master_2026.json`, версия `0.1.0-research-starter`, создан 2026-05-14.
Это **стартовый исследовательский каталог**, а не проверенная база данных. Приложение показывает это продавцу
и нигде не выдаёт непроверенные модели или варианты за проверенные.

Обновлено: 2026-11-22.

## 1. Что реализовано полностью

### Структура категорий: 14 категорий и 115 подкатегорий
Каждая подкатегория получает свою схему формы. Одна и та же схема используется для создания, редактирования,
проверки, поиска, фильтров и карточки объявления.

| Недвижимость | 10 | — (не нужен) |
| Телефоны и электроника | 13 | смартфоны / ноутбуки / ТВ / бытовая техника (см. §2) |

Для каждой подкатегории реализовано:
- **Поля формы из JSON:** типы, обязательность, единицы (TJS, м², км, л, ГБ, %, дюймы, сотки, см, мм).
- **Ограничения:** min/max, `min_exclusive`, год не больше «текущий + 1».
- **Перекрёстное правило:** этаж ≤ этажности.
- **Условные поля `show_if`:** операторы equals, in, not_in, not_empty. Скрытые значения не сохраняются.
- **Предустановки подкатегорий.** Например, «Продажа квартир» сама выставляет тип сделки `sale`, а «Аренда квартир» разрешает только аренду.
- **Цена в TJS.** Режимы цены:
  - обычная цена;
  - «бесплатно» для категории «Отдам бесплатно»;
  - без цены для «Работы»: вместо цены показывается зарплата;
  - «/мес» и «/сутки» для аренды.
- **Фото:** не больше 16, минимум берётся из схемы.
- **Фильтры из раздела `filters`.** Списки работают как «любой из», да/нет — как «только да», числа — как диапазоны, бренд и модель — через справочник, текст — как «содержит».
- **Подписи на русском и таджикском** для каждой категории, поля и варианта ответа. Тест падает, если хоть одной подписи не хватает.

### Хранилище каталога
- **Версии.** Активная версия и одна предыдущая хранятся в Hive (`catalog`), с контрольной суммой sha256 и источником (`bundled` или `remote`).
- **Работа без сети:** при первом запуске каталог ставится из встроенного файла и дальше работает офлайн.
- **Откат** на предыдущую версию: из инструментов разработчика или через API репозитория.
- **Синхронизация.** `GET /v1/catalog/manifest` → `GET /v1/catalog`. Новая версия ставится только если она новее текущей и прошла разбор. При ошибке текущий каталог остаётся как был.
- **Импорт проверенных данных.** У каждой записи обязательны поля `source_url`, `source_type`, `verified_at`, `import_batch_id`, `license_or_terms`, `market_region`, `confidence` и `status`; статус должен быть `verified` или `approved`.
  - Записи без этих полей отклоняются с указанием причины.
  - Дубликаты нормализуются.
  - Пакет можно удалить.
  - В режиме разработки: «Инструменты разработчика → Импорт проверенных данных» (JSON из буфера обмена).
- **Варианты памяти (ГБ), RAM, процессоры, поколения и породы** предлагаются списком только из проверенных импортов. Пока их нет, продавец вводит значение вручную.

## 3. Чего нет (поля работают только в режиме ручного ввода)

- **Профессии** (Работа → `occupation_id`): классификатора профессий для Таджикистана нет.
- **Виды и породы животных** (`species`, `breed`).
- **Серии и линейки** электроники (`series_id`).
- **Поколения авто** (`generation_id`).
- **Справочник шин и дисков** и каталог **запчастей**.
- **Бренды** игровых приставок, аудиотехники, камер, сетевого оборудования и бизнес-оборудования: в JSON их нет.
- **Районы и населённые пункты.** В JSON есть только 5 регионов первого уровня и список городов. В приложении остаётся прежний справочник: районы есть у Душанбе, остальное — города.
- **Отметка на карте** (`map_pin`): нужен поставщик карт; сейчас показывается пояснение.
- **Портфолио в «Услугах»** пропущено: в JSON у поля невалидный тип (`false`). Предупреждение пишется при разборе.
- **Очередь модерации** для значений «Нет в списке»: нужен сервер. Сейчас такие значения просто помечаются как ручные.

## 4. Проверка по официальным источникам — не выполнена

Сетевая политика этой среды заблокировала официальные источники (ответ прокси 403):
- `vpic.nhtsa.dot.gov` — марки и модели авто;
- `www.apple.com` и `support.apple.com`;
- `www.samsung.com`;
- `www.onetcenter.org` — профессии.

Поэтому ни одна модель и ни один вариант не проверены, и в каталог **не добавлено ничего, чего нет в исходном JSON**.

Чтобы расширить каталог:
1. Получить данные из разрешённого источника (vPIC, официальные страницы характеристик, лицензированный датасет).
2. Оформить их пакетом импорта с обязательными полями (§1). Пример — в `test/unit/catalog_test.dart`, группа «authorized imports».
3. Загрузить пакет: через `/v1/catalog` (production) или через инструменты разработчика (dev).
