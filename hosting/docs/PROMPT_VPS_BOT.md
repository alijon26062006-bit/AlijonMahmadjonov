# Промпт: раздел «VPS‑серверы» в боте (продажа серверов Hetzner Cloud)

> Скопируйте всё ниже целиком и отдайте разработчику или ИИ, который будет дорабатывать бота.
> Факты об API Hetzner в этом тексте сверены с официальной спецификацией OpenAPI
> (https://docs.hetzner.cloud/cloud.spec.json) и справкой по оплате (https://docs.hetzner.com/cloud/billing/faq/), ноябрь 2026.

---

## Роль и задача

Ты — опытный Python‑разработчик. В существующего Telegram‑бота (Python, aiogram 3) нужно добавить
**отдельный раздел «🖥 VPS‑серверы»**, через который клиенты покупают облачные серверы у Hetzner Cloud
и сами ими управляют. Бот — посредник (реселлер): сервер создаётся в нашем проекте Hetzner по API,
клиент платит нам в долларах с наценкой 20 %, мы платим Hetzner.

Не ломай существующие функции бота. Новый код — отдельным модулем (например, `bot/vps/`),
со своими таблицами в базе и своими обработчиками.

## Что должно уметь (функции раздела)

**Для клиента**
1. **Каталог.** Все страны и дата‑центры, которые есть у Hetzner сейчас (не захардкоженный список, а из API),
   с флагом страны и городом. В каждой локации — только тарифы, которые там реально доступны.
2. **Тарифы.** Для каждого: vCPU, RAM, диск, включённый трафик, архитектура (x86/ARM), тип CPU
   (shared/dedicated) и **цена в долларах в месяц = цена Hetzner + 20 %** (формула ниже).
3. **Заказ (пошагово, inline‑кнопки, FSM):** страна/локация → тариф → ОС → имя сервера → подтверждение
   с итоговой ценой → оплата с баланса клиента в боте → создание сервера → сообщение с IP, логином `root`
   и паролем (один раз, под спойлером, с советом удалить сообщение).
4. **Мои серверы:** список со статусом (🟢 работает / ⚪ выключен / 🟡 в процессе), IP, тарифом,
   датой окончания оплаты.
5. **Карточка сервера:** включить, выключить (мягко), перезагрузить, принудительно выключить,
   сменить root‑пароль, переустановить ОС, удалить; трафик за месяц; нагрузка CPU/сеть/диск за час/сутки
   (текстом или картинкой графика).
6. **Опасные действия** (удаление, переустановка, смена пароля) — только после подтверждения кнопкой
   «Да, удалить» и повторного выбора; удаление — с вводом имени сервера.

**Для администратора (владельца бота)**
7. Уведомления: новый заказ, ошибка Hetzner, приостановка сервера за неуплату.
8. Команда сводки: сколько серверов, выручка в месяц, расходы у Hetzner в месяц (по ценам API).
9. Настройка курса EUR→USD (если аккаунт Hetzner в евро) и наценки (по умолчанию 20 %).

**Автоматически (фоновая задача раз в 10 минут)**
10. Помесячное продление с баланса клиента. За 3 дня до продления, если денег не хватает, — напоминание.
11. Не хватило денег → через 3 дня сервер **выключается**, а ещё через 14 дней **удаляется** у Hetzner
    (за 3 дня до удаления — предупреждение клиенту). Важно: Hetzner берёт деньги и за выключенный сервер,
    поэтому должников нужно удалять, иначе платим мы.

## Hetzner Cloud API — всё, что нужно знать

### Основы
- Базовый адрес: `https://api.hetzner.cloud/v1`
- Авторизация: заголовок `Authorization: Bearer <HETZNER_TOKEN>`.
  Токен создаётся в Hetzner Console → проект → Security → API tokens, права **Read & Write**
  (по умолчанию стоит Read — с ним создать сервер нельзя, Hetzner вернёт `403 forbidden`).
  Токен хранить только в переменных окружения, **никогда не писать в лог и не показывать в боте**.
- Ошибки приходят так: `{"error": {"code": "invalid_input", "message": "...", "details": {...}}}`.
  Коды: `unauthorized`, `forbidden`, `not_found`, `invalid_input`, `json_error`, `locked`, `conflict`,
  `rate_limit_exceeded`, `resource_limit_exceeded`, `resource_unavailable`, `uniqueness_error`,
  `protected`, `maintenance`, `unavailable`, `timeout`, `server_error`, `service_error`, `bad_gateway`,
  а у `POST /servers` ещё `placement_error` (нет места в локации).
  Каждый код перевести в понятное клиенту сообщение на русском.
- Лимит запросов: в час на проект (заголовки `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`),
  при превышении — `429`. **Кэшировать**: каталог и цены — 1 час, статус сервера — 10 секунд, метрики — 1 минута.
- Пагинация: `?page=1&per_page=50` (по умолчанию 25, максимум 50); в ответе `meta.pagination.next_page`.
  Заголовок `Link` устарел — не использовать.

### Каталог: страны, тарифы, ОС, цены
| Запрос | Что взять из ответа |
|---|---|
| `GET /locations` | `locations[]`: `name` (например `fsn1`), `city`, `country` (ISO‑код, `DE`/`FI`/`US`/`SG`…), `network_zone`, `description` |
| `GET /server_types` | `server_types[]`: `name` (например `cx23`), `cores`, `memory` (ГБ), `disk` (ГБ), `architecture` (`x86`/`arm`), `cpu_type` (`shared`/`dedicated`), `category`, `deprecation` (если не `null` — не продавать), `locations[]` с полями `name`, `available` (false — временно нет в этой локации), `recommended`, `deprecation`; `prices[]` с полями `location`, `price_hourly`, `price_monthly` (`{net, gross}`), `included_traffic` (байты в месяц), `price_per_tb_traffic` |
| `GET /images?type=system&architecture=x86` | `images[]`: `name` (передаётся при создании, например `ubuntu-24.04`), `description`, `os_flavor`, `os_version`, `deprecation`. Для ARM‑тарифов — `architecture=arm` |
| `GET /pricing` | `pricing.currency` — **валюта аккаунта** (EUR или USD), `pricing.vat_rate`, `pricing.primary_ips[]` — цена публичного IPv4 по локациям (`type`, `prices[]: location, price_hourly, price_monthly`) |

Правила показа каталога:
- Страны и города брать из `/locations`, **ничего не хардкодить** (Hetzner добавляет и закрывает локации и тарифы;
  например, в 2026 тарифы `cx22` заменены на `cx23`).
- Тариф показывать в локации, только если у него там `available: true` и нет `deprecation`.
- Флаг страны строить из ISO‑кода (`DE` → 🇩🇪).

### Цена для клиента: Hetzner + 20 %, в долларах
Все цены в API — в валюте владельца проекта (`pricing.currency`). Берём **net** (без НДС: для клиентов
вне ЕС Hetzner НДС не начисляет).

```
себестоимость_в_месяц = price_monthly.net тарифа в этой локации
                       + price_monthly.net публичного IPv4 (pricing.primary_ips, type=ipv4) в этой локации
цена_клиенту_USD = округлить_вверх_до_цента( себестоимость_в_месяц × курс(валюта_аккаунта → USD) × 1.20 )
```
- Если `pricing.currency == "USD"`, курс = 1.
- Если EUR — курс задаёт админ командой (надёжнее) или берётся раз в сутки из открытого API
  (например, `https://open.er-api.com/v6/latest/EUR` → `rates.USD`) с сохранением последнего значения в базе.
- Наценку (20 %) хранить в настройках, а не в коде.
- Цену фиксировать в момент заказа (в таблице сервера) и продлевать по ней; при изменении цен у Hetzner
  новые цены — только для новых заказов.

### Как Hetzner берёт деньги (важно для расчётов)
- У сервера **почасовая цена и месячный потолок**: платим меньшее из «часы × цена_часа» и «месячная цена».
- Начатый час считается целым.
- **Удалили сервер — оплата остановилась.** Выключенный сервер **продолжает оплачиваться**.
- Трафик сверх `included_traffic` оплачивается отдельно (`price_per_tb_traffic`).
- Счёт приходит в начале месяца за прошлый (постоплата). **Баланса аккаунта в API нет** — показать можно
  только расчётные расходы по текущим серверам.

### Создание сервера
`POST /servers`, тело:
```json
{
  "name": "client42-web-17",
  "server_type": "cx23",
  "image": "ubuntu-24.04",
  "location": "fsn1",
  "start_after_create": true,
  "ssh_keys": ["bot-panel-key"],
  "user_data": "#cloud-config\n...",
  "labels": {"bot_user": "42", "bot_server": "17"},
  "public_net": {"enable_ipv4": true, "enable_ipv6": true}
}
```
- Обязательные поля: `name`, `server_type`, `image`. Имя уникально **в проекте** — добавляй к имени клиента номер заказа.
- Ответ `201`: `server` (`id`, `status`, `public_net.ipv4.ip`, `public_net.ipv6.ip` — это сеть `/64`,
  например `2001:db8::/64`), `action`, `next_actions`, `root_password`.
- `root_password` приходит, **только если не переданы `ssh_keys`**. В этом случае Hetzner ещё и **присылает
  пароль владельцу аккаунта на почту** и **требует сменить пароль при первом входе**. Поэтому для продажи
  рекомендуемый способ — с ключом бота (ниже).
- `user_data` (cloud‑init) — до 32 КиБ.
- Статусы сервера: `running`, `initializing`, `starting`, `stopping`, `off`, `deleting`, `migrating`,
  `rebuilding`, `unknown`.
- Ход операции: `GET /actions/{id}` → `status`: `running` / `success` / `error`, плюс `progress` и `error`.

### Root‑пароль без письма Hetzner и без требования его сменить (рекомендуется)
1. Один раз сгенерировать SSH‑ключ бота (например, RSA 3072 через `paramiko`), хранить закрытый ключ
   в файле с правами `600`.
2. Зарегистрировать открытый ключ в проекте: `GET /ssh_keys?name=bot-panel-key`, если нет —
   `POST /ssh_keys {"name": "bot-panel-key", "public_key": "ssh-rsa AAAA..."}`.
3. Создавать серверы с `"ssh_keys": ["bot-panel-key"]` и cloud‑init, который разрешает вход root по паролю:
   ```yaml
   #cloud-config
   ssh_pwauth: true
   write_files:
     - path: /etc/ssh/sshd_config.d/00-bot.conf
       content: "PermitRootLogin yes\nPasswordAuthentication yes\n"
   runcmd:
     - [sh, -c, "systemctl restart ssh 2>/dev/null || systemctl restart sshd"]
   ```
4. Сгенерировать пароль клиенту самому (12+ символов: строчные, заглавные, цифры, символы) или принять его пароль.
5. Дождаться `status == running` и IP, зайти по SSH ключом бота (`paramiko`, повторять попытки ~раз в 6 с до 2–3 минут)
   и выполнить:
   `chpasswd` (пароль передать **через stdin** строкой `root:ПАРОЛЬ`, не в командной строке),
   затем `chage -d "$(date +%Y-%m-%d)" root` — чтобы система не требовала сменить пароль при входе.
6. Ключ хоста сервера запомнить при первом подключении и сверять при следующих.
7. Пароль **не хранить** в базе; клиенту показать один раз.

Запасной путь, если клиент удалил ключ бота: `POST /servers/{id}/actions/reset_password`
(работает только на включённом сервере с qemu‑guest‑agent, возвращает `root_password`), затем войти
по SSH с этим паролем и так же выполнить `chpasswd` + `chage`.

### Управление сервером
| Действие | Запрос |
|---|---|
| Статус, IP, трафик | `GET /servers/{id}` → `status`, `public_net`, `outgoing_traffic`, `ingoing_traffic`, `included_traffic` (байты за текущий расчётный период), `locked` |
| Включить | `POST /servers/{id}/actions/poweron` |
| Выключить мягко | `POST /servers/{id}/actions/shutdown` |
| Выключить принудительно | `POST /servers/{id}/actions/poweroff` |
| Перезагрузить | `POST /servers/{id}/actions/reboot` (мягко) или `/actions/reset` (жёстко) |
| Переустановить ОС | `POST /servers/{id}/actions/rebuild` тело `{"image": "...", "user_data": "..."}` — **все данные стираются**; сервер сам выключается перед переустановкой; `root_password` в ответе только если сервер без SSH‑ключей; после переустановки снова поставить пароль по шагам выше |
| Удалить | `DELETE /servers/{id}` — оплата у Hetzner прекращается |

Все действия возвращают `action` (`201`). Если сервер занят другой операцией — ошибка `locked`, повторить позже.

### Нагрузка (графики)
`GET /servers/{id}/metrics?type=cpu,disk,network&start=<RFC3339>&end=<RFC3339>&step=<секунды>`
- Ответ: `metrics.time_series` — ключи `cpu`, `disk.0.iops.read`, `disk.0.iops.write`, `disk.0.bandwidth.read`,
  `disk.0.bandwidth.write` (байт/с), `network.0.pps.in`, `network.0.pps.out`, `network.0.bandwidth.in`,
  `network.0.bandwidth.out` (байт/с); значения — пары `[timestamp, "строка-число"]`.
- **CPU считается на одно ядро:** 100 = одно ядро загружено полностью; у 4‑ядерного сервера 400 = 100 %.
  Для показа клиенту делить на число vCPU.
- Не больше 500 точек на запрос; без `step` Hetzner сам подберёт до 200 точек; хранятся 30 дней.
- Памяти (RAM) и процессов в API нет — только если поставить на сервер своего агента.

## Деньги и безопасность в боте
- Порядок заказа: проверить данные → **списать с баланса** → создать сервер в Hetzner →
  при любой ошибке Hetzner **сразу вернуть деньги** на баланс и сообщить клиенту понятную причину.
- Каждое действие с сервером — только если сервер принадлежит этому пользователю Telegram (проверка владельца в базе).
- Ограничить новых клиентов (например, 1 сервер), пока админ не подтвердит: если с сервера пойдёт спам или атака,
  Hetzner может заблокировать **весь** аккаунт.
- Ограничить частоту действий (например, не больше 30 действий с серверами за 5 минут на пользователя).
- `callback_data` в Telegram — не больше 64 байт: передавать короткие id, а не имена.
- Пароли — под `<tg-spoiler>`, с подсказкой удалить сообщение после сохранения.
- Все действия писать в журнал (кто, что, когда), без паролей и токенов.

## Таблицы (минимум)
- `vps_servers`: id, tg_user_id, hetzner_id, name, server_type, location, image, ipv4, ipv6, status,
  price_usd_month, cost_month (себестоимость в валюте Hetzner), paid_until, suspended_at, deleted_at, created_at.
- `vps_settings`: markup (0.20), fx_rate, fx_updated_at, new_user_limit.
- Использовать существующий баланс/кошелёк бота; если его нет — таблица `balances` и журнал операций.

## Что проверить (критерии готовности)
- Каталог показывает все текущие локации Hetzner и только доступные в них тарифы.
- Цена = (цена Hetzner net + IPv4) × курс × 1.20, в долларах, округлено вверх до цента.
- Заказ создаёт сервер, клиент получает IP и пароль и входит по SSH **без требования сменить пароль**; письма от Hetzner нет.
- Ошибка Hetzner при заказе → деньги возвращены, клиент видит понятное сообщение.
- Вкл/выкл/перезагрузка/смена пароля/переустановка/удаление работают и доступны только владельцу.
- Графики CPU показывают 0–100 % (с делением на число ядер).
- Продление, напоминание, выключение через 3 дня и удаление через 14 дней после неоплаты работают.
- Тесты на всё это — с подменой Hetzner (`httpx.MockTransport`), без настоящего токена.
