# AM Cloud: продажа VPS и доменов на Hetzner Cloud

Сайт и личный кабинет хостинга. Клиент сам:

- заказывает сервер: тариф, локация, ОС, свой root‑пароль;
- включает, выключает и перезагружает сервер;
- **меняет root‑пароль** на свой или генерирует случайный;
- смотрит **графики**: процессор, память, сеть, диск, топ процессов за час, сутки и неделю;
- регистрирует или добавляет домены и **управляет DNS** (A, AAAA, CNAME, MX, TXT, NS, SRV, CAA);
- пополняет баланс. Серверы продлеваются помесячно, домены раз в год.

Админ видит клиентов, выручку и журнал действий, может пополнить баланс клиента и проверить тарифы у Hetzner.

## Как это устроено

| Что | Откуда берётся |
|---|---|
| Создание, питание, переустановка, удаление серверов | Hetzner Cloud API (`/servers`) |
| CPU, сеть, диск | Hetzner Cloud API (`/servers/{id}/metrics`) |
| Память, место на диске, нагрузка, процессы | Агент `agent/amcloud_agent.py`. Ставится на сервер автоматически через cloud‑init и раз в 30 секунд отправляет данные на `PUBLIC_URL/api/agent/report` |
| Свой root‑пароль | Hetzner сбрасывает пароль на временный (`reset_password`), панель заходит по SSH и ставит пароль клиента через `chpasswd`. Пароль не хранится в базе |
| Случайный root‑пароль | Hetzner `reset_password`, пароль показывается клиенту один раз |
| DNS‑зоны и записи | Hetzner Cloud API (`/zones`, `/zones/{zone}/rrsets`). Тот же токен, что и для серверов |
| Регистрация доменов | Пока демо. Для настоящей нужен реселлерский договор с регистратором (ResellerClub, Openprovider и т.п.) |
| Оплата | Пока демо‑кнопка «Пополнить» и пополнение админом. Платёжную систему нужно подключить отдельно |

## Запуск на своём компьютере (демо, без ключей)

```bash
cd hosting
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # укажите ADMIN_EMAIL — этот email станет админом
.venv/bin/python run.py       # http://127.0.0.1:8000
```

В демо‑режиме серверы, графики и DNS симулируются, поэтому кабинет можно показывать клиентам.

## Подключение Hetzner

1. Зарегистрируйтесь на hetzner.com и создайте проект в **Hetzner Console**.
2. В проекте откройте **Security → API tokens → Generate API token**, права **Read & Write**. Токен показывается один раз.
3. В `.env`:
   ```
   VPS_PROVIDER=hetzner
   DNS_PROVIDER=hetzner
   HETZNER_TOKEN=ваш_токен
   PUBLIC_URL=https://my.ваш-домен.com
   ```
4. Перезапустите панель и откройте **Админку**. В блоке «Провайдер» видно, какие типы серверов из `catalog.json` реально есть у Hetzner и сколько они стоят. Если у типа написано «нет», поменяйте `server_type` в `catalog.json`.
5. Свои цены, тарифы, локации, ОС и доменные зоны задаются в `catalog.json`.

**Важно про Hetzner (ноябрь 2026):**
- С июня 2026 Hetzner ограничивает создание новых облачных серверов для новых клиентов и части старых. Если при заказе приходит ошибка «тариф недоступен», напишите в поддержку Hetzner и попросите снять ограничение для проекта.
- Лимит Hetzner API — 3600 запросов в час на проект. Панель кэширует статусы (8 с) и графики (50 с), но при сотнях клиентов понадобится несколько проектов.
- Разрешена ли перепродажа серверов, уточните в договоре Hetzner или у их поддержки.

## Запуск в интернете

- Панель запускается командой `uvicorn run:app --host 127.0.0.1 --port 8000 --proxy-headers` под systemd, перед ней ставится nginx с HTTPS (Let's Encrypt).
- В `.env` для продакшена:
  - `COOKIE_SECURE=true`;
  - длинный `SECRET_KEY`;
  - `DEMO_PAYMENTS=false`.
- `PUBLIC_URL` должен открываться из интернета, иначе агенты на серверах клиентов не смогут прислать память и процессы.
- База данных лежит в одном файле `data/hosting.db`. Делайте его резервную копию.

## Безопасность

- Пароли аккаунтов хранятся как хэш scrypt. Сессии в cookie с флагами HttpOnly и SameSite. От CSRF защищают заголовок `X-Requested-With` и токен сессии.
- Смена root‑пароля, переустановка ОС и удаление сервера требуют пароль от кабинета.
- Попытки входа и чувствительные действия ограничены по частоте.
- Новый root‑пароль передаётся на сервер через stdin команды `chpasswd`, а не в командной строке. Ключ SSH сервера запоминается при первом подключении: если он подменён, подключение отклоняется.
- Все действия клиентов пишутся в журнал (админка → «Журнал действий»).

## Тесты

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
```

54 теста:
- API в демо‑режиме;
- клиент Hetzner на подставных ответах;
- смена пароля по SSH против настоящего SSH‑сервера внутри теста;
- проверка DNS‑записей, биллинг.

## Структура

```
app/main.py           HTTP API и раздача страниц
app/services.py       заказ серверов, пароли, графики, домены, DNS, биллинг
app/providers/        hetzner.py — Hetzner Cloud API; demo.py — симуляция
app/ssh.py            установка root-пароля по SSH
app/cloudinit.py      cloud-init: агент + вход root по паролю
agent/                агент для серверов клиентов
static/               сайт (index.html) и кабинет (app.html)
catalog.json          тарифы, локации, ОС, доменные зоны и цены
prototype/            первый концепт интерфейса
```
