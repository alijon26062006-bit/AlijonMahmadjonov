# Бозор — доска объявлений в Telegram и браузере

Недвижимость · Авто · Техника · Запчасти — для Таджикистана.

Telegram-бот (подача объявлений диалогом), Mini App и веб-сайт (один код),
модерация в приватной группе, автопостинг в канал, фото хранятся в Telegram.

## Что внутри

| Часть | Стек | Папка |
|---|---|---|
| Бот | Python 3.12, aiogram 3 | `backend/app/bot` |
| API | FastAPI, SQLAlchemy 2 async | `backend/app/api` |
| Движок категорий | декларативные схемы, JSONB | `backend/app/schemas_engine` |
| Клиент (Mini App + сайт) | React 18, Vite, TypeScript | `miniapp/` |
| Фоновые задачи | arq (публикация, автоархив) | `backend/app/workers` |
| БД | PostgreSQL 16, Redis 7 | docker-compose |

**15 категорий** в 4 направлениях. Новая категория = один вызов
`make_schema(...)` в `backend/app/schemas_engine/categories.py` — мастер в боте,
веб-форма, фильтры и пост в канал построятся сами. Без миграций.

**Идентификаторы**: VIN (с контрольной суммой, автозаполнение года и марки),
номер кузова японских авто, IMEI (Луна, 15 цифр), артикулы. Дубликаты и
чёрный список подсвечиваются модератору.

## Быстрый старт

На чистом VPS (Ubuntu/Debian) — один скрипт. Он поставит Docker, спросит
данные из Telegram, сгенерирует пароли и всё запустит:

```bash
sudo bash install.sh
```

Вручную, если предпочитаете контроль:

```bash
cp .env.example .env      # заполнить BOT_TOKEN и остальное
docker compose up -d --build
```

Поднимутся: `db`, `redis`, `migrate` (схема + справочники: 15 городов,
265 брендов, 526 моделей авто), `api` (:8000), `bot` (polling), `worker`,
`miniapp` (:8080).

Проверка: `curl localhost:8000/health` → `{"db":"ok"}`; в Telegram — `/start`.

## Настройка Telegram (по шагам)

1. **@BotFather** → `/newbot` → токен в `BOT_TOKEN`.
   Затем `/setprivacy` → **Disable** (иначе бот не увидит сообщения админов
   в группе модерации).
2. **@BotFather** → `/newapp` → выбрать бота, указать URL Mini App
   (`WEBAPP_URL`), short name → в `MINIAPP_SHORT_NAME`.
3. Создать **канал** публикаций → добавить бота администратором с правом
   публиковать → id канала в `CHANNEL_ID` (переслать пост в @userinfobot).
4. Создать **приватную группу модерации** → добавить бота → id в
   `ADMIN_CHAT_ID`. Свои tg_id → `ADMIN_IDS`.
5. Создать **приватный чат-хранилище** (для фото, загружаемых с сайта) →
   добавить бота → id в `STORAGE_CHAT_ID`.
6. Для Mini App и сайта нужен HTTPS — см. следующий раздел. **Боту домен
   не нужен**: он работает по polling и запускается сразу после шага 4.

## Запуск 24/7 без покупки домена

Единственное обязательное условие — машина, которая не выключается
(VPS от ~5 $/мес или свой всегда включённый компьютер). Домен покупать
не обязательно.

### Только бот — вообще ничего не требуется

Бот сам ходит к Telegram за сообщениями (polling): ни домена, ни HTTPS,
ни открытых портов. Подача объявлений, модерация и автопостинг в канал
работают круглосуточно.

```bash
docker compose up -d db redis migrate bot worker
```

### Бот + Mini App и сайт — нужен HTTPS, но бесплатный

Telegram открывает Mini App только по валидному HTTPS. Самоподписанный
сертификат не подойдёт. Бесплатный постоянный поддомен:

1. Зарегистрировать поддомен на **DuckDNS** (duckdns.org, вход через
   Google/GitHub) — получится адрес вида `bozor.duckdns.org`.
2. Указать там IP вашего сервера.
3. В `.env` прописать:
   ```
   DOMAIN=bozor.duckdns.org
   WEBAPP_URL=https://bozor.duckdns.org
   API_PUBLIC_URL=
   CORS_ORIGINS=https://bozor.duckdns.org
   ```
   `API_PUBLIC_URL` оставляем пустым: сайт и API отдаются с одного адреса,
   nginx проксирует `/api` внутрь.
4. Запустить с Caddy — он сам получит и будет продлевать сертификат:
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
   ```
5. Этот же адрес указать в @BotFather (`/newapp` и `/setmenubutton`).

Порты 80 и 443 должны быть открыты. Аналогично работают No-IP и FreeDNS;
при желании обычный домен (~2–10 $ в год) подключается заменой `DOMAIN`.

### Если на сервере уже работает nginx

Частый случай: порт 80 занят другим сервисом (панель, чужой сайт). Тогда
Caddy не нужен — наш проект прячется за существующий nginx.

1. Запустить без Caddy, подобрав свободные порты:
   ```bash
   for p in $(seq 8001 8099); do ss -ltn | grep -q ":$p " || { echo "API_PORT=$p"; break; }; done
   for p in $(seq 8090 8199); do ss -ltn | grep -q ":$p " || { echo "MINIAPP_PORT=$p"; break; }; done
   # вписать полученные значения в .env, затем:
   docker compose up -d --build
   ```
2. Добавить сайт в существующий nginx (`/etc/nginx/sites-enabled/bozor`):
   ```nginx
   server {
       listen 80;
       server_name ВАШ-ДОМЕН;
       client_max_body_size 12m;
       location / {
           proxy_pass http://127.0.0.1:8090;   # = MINIAPP_PORT
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```
3. `nginx -t && systemctl reload nginx`
4. Сертификат: `certbot --nginx -d ВАШ-ДОМЕН` (редирект на HTTPS — вариант 2)

**Проверьте, что домен ведёт на ваш сервер**, прежде чем выпускать сертификат:
`dig +short ВАШ-ДОМЕН` и `curl -s ifconfig.me` должны совпасть. Занятое кем-то
имя на DuckDNS резолвится на чужой IP — Let's Encrypt тогда падает с таймаутом,
а токен не подходит к домену.

### Быстрая проверка без сервера

Для разовой демонстрации подойдёт временный туннель — домен не нужен совсем:

```bash
cloudflared tunnel --url http://localhost:8080
```

Даст случайный адрес `*.trycloudflare.com`, его временно прописать в
BotFather. Адрес меняется при каждом перезапуске, поэтому для постоянной
работы используйте вариант с DuckDNS выше.

## Разработка без Docker

```bash
# БД и Redis любым способом, затем:
cd backend
pip install -r requirements.txt
python -m app.db.create                      # схема + справочники
uvicorn app.api.main:app --reload            # API :8000
python -m app.bot                            # бот (polling)
arq app.workers.worker.WorkerSettings        # воркер

cd ../miniapp
npm install && npm run dev                   # клиент :5173 (проксирует /api)
```

Mini App в Telegram требует HTTPS — для локальной проверки:
`cloudflared tunnel --url http://localhost:5173`, полученный адрес
временно прописать в BotFather (`/newapp`) и в `WEBAPP_URL`.

## Как это работает

**Подача в боте.** Универсальный FSM (`bot/handlers/wizard.py`) читает схему
категории и задаёт вопросы по шагам: кнопки для списков, текст для чисел,
альбомы фото склеиваются middleware'ом, «Назад» — стек истории, из
предпросмотра можно изменить любое поле. Состояние живёт в Redis —
переживает рестарт.

**Модерация.** Объявление уходит в группу админов медиагруппой + карточка
с кнопками. Двойное нажатие исключено (`SELECT ... FOR UPDATE`). Одобрение
ставит задачу в arq → пост в канал (caption ≤ 1024, кнопка-ссылка на Mini App
через `startapp`) → уведомление автору.

**Каталог.** Фильтры принимаются строго по белому списку из схемы: общие
поля — колонки, специфичные — JSONB (`attrs->>key`). Пагинация — keyset
по `(published_at, id)`. Цены нормализуются в USD.

**Фото.** Хранятся в Telegram (file_id). Отдача через `/api/photos/<uuid>`
с кэшем: диск → Redis (file_path живёт ~1 час) → браузер (immutable + ETag).
Загрузка с сайта: файл проверяется и пересылается ботом в чат-хранилище —
получается тот же file_id, файлового хранилища на сервере нет.

**Вход на сайте.** Кнопка «Войти через Telegram» → одноразовый код →
`t.me/<бот>?start=login_<код>` → «Подтвердить вход» в боте → сессия.
В Mini App вход автоматический по `initData` (HMAC-проверка на сервере).

**Админ-панель** (`/admin`, видна только администраторам): очередь модерации
с фото и подсветкой подозрений, жалобы, поиск и бан пользователей, добавление
городов, брендов и моделей без программиста, журнал действий и статистика.
Одобрение из панели и из кнопок в группе идёт через один сервис
(`services/moderation_service.py`) — блокировка строки исключает двойную
публикацию.

**Аренда.** У категорий аренды статус «Занято» вместо «Продано»: объявление
скрывается из каталога и возвращается одной кнопкой «Снова свободно» —
без повторной подачи.

## Структура категорий

```
Недвижимость: аренда квартиры · продажа квартиры
Авто:         продажа · аренда · автоуслуги
Техника:      продажа техники · услуги ремонта
Запчасти(8):  авто · телефоны · компьютеры · бытовая техника
              · ТВ и аудио · инструмент · мото/вело · электроника
```

Справочники (`backend/app/seed/data/`): города Таджикистана с районами
Душанбе, бренды по 9 областям применения, модели автомобилей под местный
рынок. Пересборка: `tz/data/build_dictionaries.py` в корне репозитория.

## Проверено

- Юнит: VIN/IMEI/артикулы — контрольные суммы, эталонные значения.
- Интеграционно (реальные PostgreSQL + Redis): создание объявления из данных
  мастера, конвертация валют, повтор VIN → метка модератору, каталог,
  JSONB-фильтры, keyset-пагинация без дублей, избранное, жалобы (409),
  контакты, отказ поддельной initData, коды входа — 30 проверок.
- Админ-панель: права доступа, очередь, одобрение и повторное одобрение (409),
  отклонение с причиной, жалобы, бан и разбан, запрет забанить себя,
  справочники, журнал — 31 проверка.
- Фронтенд: `tsc --noEmit` чисто, продакшен-сборка 121 КБ gzip,
  скриншоты светлой/тёмной темы и десктопа.

## Что осталось за рамками v1 (см. ТЗ в ../tz/)

Вебхук-режим бота (сейчас polling — для VPS этого достаточно), Alembic-миграции
(схема создаётся `create_all`; Alembic подключить при первом изменении схемы),
полнотекстовый поиск tsvector (сейчас ILIKE), перцептивный хеш фото,
TAC-справочник моделей по IMEI, платное продвижение.
