# Бозор — доска объявлений в Telegram и браузере

Недвижимость · Авто · Техника · Запчасти — для Таджикистана.

Telegram-бот (подача объявлений диалогом), Mini App и веб-сайт (один код),
модерация в приватной группе, автопостинг в канал, фото хранятся в Telegram.

## Что внутри

| Часть | Стек | Папка |
|---|---|---|
| Бот | Python 3.12, aiogram 3 | `backend/app/bot` |
| API | FastAPI, SQLAlchemy 2 async | `backend/app/api` |
| Движок категорий | декларативные схемы, JSONB | `backend/app/schemas_engine` |
| Клиент (Mini App + сайт) | React 18, Vite, TypeScript | `miniapp/` |
| Фоновые задачи | arq (публикация, автоархив) | `backend/app/workers` |
| БД | PostgreSQL 16, Redis 7 | docker-compose |

**15 категорий** в 4 направлениях. Новая категория = один вызов
`make_schema(...)` в `backend/app/schemas_engine/categories.py` — мастер в боте,
веб-форма, фильтры и пост в канал построятся сами. Без миграций.

**Идентификаторы**: VIN (с контрольной суммой, автозаполнение года и марки),
номер кузова японских авто, IMEI (Луна, 15 цифр), артикулы. VIN дополнительно
расшифровывается по открытой базе NHTSA, модель телефона определяется по TAC.
Дубликаты, чёрный список и расхождения с базой подсвечиваются модератору.

## Быстрый старт

На чистом VPS (Ubuntu/Debian) — один скрипт. Он поставит Docker, спросит
данные из Telegram, сгенерирует пароли и всё запустит:

```bash
sudo bash install.sh
```

Вручную, если предпочитаете контроль:

```bash
cp .env.example .env      # заполнить BOT_TOKEN и остальное
docker compose up -d --build
```

Поднимутся: `db`, `redis`, `migrate` (схема + справочники: 15 городов,
265 брендов, 526 моделей авто), `api` (:8000), `bot` (polling), `worker`,
`miniapp` (:8080).

Проверка: `curl localhost:8000/health` → `{"db":"ok"}`; в Telegram — `/start`.

## Настройка Telegram (по шагам)

1. **@BotFather** → `/newbot` → токен в `BOT_TOKEN`.
   Затем `/setprivacy` → **Disable** (иначе бот не увидит сообщения админов
   в группе модерации).
2. **@BotFather** → `/newapp` → выбрать бота, указать URL Mini App
   (`WEBAPP_URL`), short name → в `MINIAPP_SHORT_NAME`.
3. Создать **канал** публикаций → добавить бота администратором с правом
   публиковать → id канала в `CHANNEL_ID` (переслать пост в @userinfobot).
4. Создать **приватную группу модерации** → добавить бота → id в
   `ADMIN_CHAT_ID`. Свои tg_id → `ADMIN_IDS`.
5. Создать **приватный чат-хранилище** (для фото, загружаемых с сайта) →
   добавить бота → id в `STORAGE_CHAT_ID`.
6. Для Mini App и сайта нужен HTTPS — см. следующий раздел. **Боту домен
   не нужен**: он работает по polling и запускается сразу после шага 4.

## Запуск 24/7 без покупки домена

Единственное обязательное условие — машина, которая не выключается
(VPS от ~5 $/мес или свой всегда включённый компьютер). Домен покупать
не обязательно.

### Только бот — вообще ничего не требуется

Бот сам ходит к Telegram за сообщениями (polling): ни домена, ни HTTPS,
ни открытых портов. Подача объявлений, модерация и автопостинг в канал
работают круглосуточно.

```bash
docker compose up -d db redis migrate bot worker
```

### Бот + Mini App и сайт — нужен HTTPS, но бесплатный

Telegram открывает Mini App только по валидному HTTPS. Самоподписанный
сертификат не подойдёт. Бесплатный постоянный поддомен:

1. Зарегистрировать поддомен на **DuckDNS** (duckdns.org, вход через
   Google/GitHub) — получится адрес вида `bozor.duckdns.org`.
2. Указать там IP вашего сервера.
3. В `.env` прописать:
   ```
   DOMAIN=bozor.duckdns.org
   WEBAPP_URL=https://bozor.duckdns.org
   API_PUBLIC_URL=
   CORS_ORIGINS=https://bozor.duckdns.org
   ```
   `API_PUBLIC_URL` оставляем пустым: сайт и API отдаются с одного адреса,
   nginx проксирует `/api` внутрь.
4. Запустить с Caddy — он сам получит и будет продлевать сертификат:
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
   ```
5. Этот же адрес указать в @BotFather (`/newapp` и `/setmenubutton`).

Порты 80 и 443 должны быть открыты. Аналогично работают No-IP и FreeDNS;
при желании обычный домен (~2–10 $ в год) подключается заменой `DOMAIN`.

### Если на сервере уже работает nginx

Частый случай: порт 80 занят другим сервисом (панель, чужой сайт). Тогда
Caddy не нужен — наш проект прячется за существующий nginx.

1. Запустить без Caddy, подобрав свободные порты:
   ```bash
   for p in $(seq 8001 8099); do ss -ltn | grep -q ":$p " || { echo "API_PORT=$p"; break; }; done
   for p in $(seq 8090 8199); do ss -ltn | grep -q ":$p " || { echo "MINIAPP_PORT=$p"; break; }; done
   # вписать полученные значения в .env, затем:
   docker compose up -d --build
   ```
2. Добавить сайт в существующий nginx (`/etc/nginx/sites-enabled/bozor`):
   ```nginx
   server {
       listen 80;
       server_name ВАШ-ДОМЕН;
       client_max_body_size 12m;
       location / {
           proxy_pass http://127.0.0.1:8090;   # = MINIAPP_PORT
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```
3. `nginx -t && systemctl reload nginx`
4. Сертификат: `certbot --nginx -d ВАШ-ДОМЕН` (редирект на HTTPS — вариант 2)

**Проверьте, что домен ведёт на ваш сервер**, прежде чем выпускать сертификат:
`dig +short ВАШ-ДОМЕН` и `curl -s ifconfig.me` должны совпасть. Занятое кем-то
имя на DuckDNS резолвится на чужой IP — Let's Encrypt тогда падает с таймаутом,
а токен не подходит к домену.

### Быстрая проверка без сервера

Для разовой демонстрации подойдёт временный туннель — домен не нужен совсем:

```bash
cloudflared tunnel --url http://localhost:8080
```

Даст случайный адрес `*.trycloudflare.com`, его временно прописать в
BotFather. Адрес меняется при каждом перезапуске, поэтому для постоянной
работы используйте вариант с DuckDNS выше.

## Разработка без Docker

```bash
# БД и Redis любым способом, затем:
cd backend
pip install -r requirements.txt
python -m app.db.create                      # схема + справочники
uvicorn app.api.main:app --reload            # API :8000
python -m app.bot                            # бот (polling)
arq app.workers.worker.WorkerSettings        # воркер

cd ../miniapp
npm install && npm run dev                   # клиент :5173 (проксирует /api)
```

Mini App в Telegram требует HTTPS — для локальной проверки:
`cloudflared tunnel --url http://localhost:5173`, полученный адрес
временно прописать в BotFather (`/newapp`) и в `WEBAPP_URL`.

## Как это работает

**Подача в боте.** Универсальный FSM (`bot/handlers/wizard.py`) читает схему
категории и задаёт вопросы по шагам: кнопки для списков, текст для чисел,
альбомы фото склеиваются middleware'ом, «Назад» — стек истории, из
предпросмотра можно изменить любое поле. Состояние живёт в Redis —
переживает рестарт.

**Права.** `ADMIN_IDS` — единственный источник правды: список сверяется при
каждом действии в боте и каждом входе в приложение. Убрали id из списка —
права снимаются, добавили — выдаются. Раньше отметка ставилась только при
регистрации, и смена списка ни на что не влияла.

**Модерация.** Разбирать заявки можно прямо в боте: кнопка «🛡 Модерация»
(видна только админам) или `/queue`. Показывается одна заявка — фотографии,
карточка, кнопки «Одобрить», «Отклонить», «Пропустить», «Бан автора».
Обработали — карточка исчезает из чата, сразу приходит следующая, в шапке
видно, сколько осталось. Пропущенные возвращаются при следующем открытии
очереди. О новой заявке каждому админу приходит короткий сигнал в личку.
Приватная группа модерации остаётся: задан `ADMIN_CHAT_ID` — карточки идут
туда, оставлен нулём — разбор только очередью в боте. Объявление уходит в
группу медиагруппой + карточка с кнопками. Двойное нажатие исключено (`SELECT ... FOR UPDATE`). Одобрение
ставит задачу в arq → пост в канал (caption ≤ 1024, кнопка-ссылка на Mini App
через `startapp`) → уведомление автору.

**Карта.** Точку на карте спрашивают только аренда и продажа квартиры —
там место действительно решает. У телефона, запчасти или услуги шаг с картой
убран: он удлинял мастер и ничего не добавлял. Признак — наличие поля типа
`geo` в схеме; координаты старых объявлений в выдачу не попадают.

**Каталог.** Фильтры принимаются строго по белому списку из схемы: общие
поля — колонки, специфичные — JSONB (`attrs->>key`). Значения списков
проверяются по схеме и на сервере — с сайта нельзя прислать свой вариант. Пагинация — keyset
по `(published_at, id)`. Цены нормализуются в USD.

**Фото.** Хранятся в Telegram (file_id). Для карточки берётся размер не
меньше 400 точек: самый первый в наборе Telegram — около 90 точек, в сетке он
выглядит мутным пятном. Отдача через `/api/photos/<uuid>`
с кэшем: диск → Redis (file_path живёт ~1 час) → браузер (immutable + ETag).
Загрузка с сайта: файл проверяется и пересылается ботом в чат-хранилище —
получается тот же file_id, файлового хранилища на сервере нет.

**Вход.** В Mini App регистрации нет вообще: `/start` в боте отдаёт кнопку
«Открыть приложение» (`web_app`), Telegram передаёт подписанные `initData`,
сервер проверяет подпись и заводит аккаунт при первом входе. Прошлая сессия
поднимается из кэша сразу, подпись проверяется фоном — профиль виден без
ожидания сети. Имя и `@username` подтягиваются при каждом входе.
На сайте в браузере: «Войти через Telegram» → одноразовый код →
`t.me/<бот>?start=login_<код>` → «Подтвердить вход» в боте → сессия.

**Админ-панель** (`/admin`, видна только администраторам): очередь модерации
с фото и подсветкой подозрений, жалобы, поиск и бан пользователей, добавление
городов, брендов и моделей без программиста, журнал действий и статистика.
Одобрение из панели и из кнопок в группе идёт через один сервис
(`services/moderation_service.py`) — блокировка строки исключает двойную
публикацию.

**Главная лента** (`/api/feed`) — перемешанная витрина по категориям с
меткой категории на карточке. Оценка складывается из четырёх слагаемых:
свежесть (вес падает вдвое за 72 часа), качество (фото, заполненность,
отклик со сглаживанием — новые не штрафуются), близость интересам (0.5 —
нейтрально, пока истории нет) и устойчивая случайность. Порядок постоянен
в течение дня для конкретного человека, назавтра обновляется. Разнообразие
принудительное: подряд не больше двух одной категории, каждое пятое место —
вне интересов, иначе человек запирается в пузыре. Веса — в настройках
(`feed_w_*`), подбираются без правки кода.

**Интересы** строятся из `listing_events` за 30 дней: обращение к продавцу
весит вдвое больше добавления в избранное и втрое — просмотра. События
собираются с первого дня: задним числом их получить неоткуда.

**Проверка номеров.** Локально: контрольная сумма VIN (9-я позиция), год по
10-му символу, марка по WMI, алгоритм Луна для IMEI, формат номера кузова.
Дальше номер пробуют опознать.

*VIN* уходит в открытую базу NHTSA (`vpic.nhtsa.dot.gov`) — реестр США,
бесплатный и без ключа: марка, модель, год, кузов, двигатель. Ответ кэшируется
на месяц, включая отрицательный, чтобы не ходить в сеть впустую. Тайм-аут
6 секунд, любой сбой означает «сведений нет» — мастер идёт дальше. Выключается
`VIN_DECODE_ENABLED=false`. Праворульные с внутреннего рынка Японии в базе
отсутствуют: у них не VIN, а номер кузова, и публичной базы по ним нет.
База не отвечает на вопрос «угнана ли машина» — платные сервисы (CarVertical,
Carfax) отвечают, но данных по Таджикистану у них почти нет.

*IMEI* — по TAC, первым восьми цифрам: они одинаковы у всей партии одной
модели. Таблица наполняется тремя путями: вручную в админ-панели
(«Справочники» → «Модели по IMEI»), импортом открытого списка
`python -m app.seed.import_tac файл.csv` (колонки со словами tac, brand,
model) и наблюдением — модератор одобрил объявление, где IMEI и модель стоят
рядом, значит пара верна. Порог `TAC_MIN_CONFIRMATIONS` (по умолчанию 1)
задаёт, сколько одобрений должны сойтись: единица означает, что площадка
учится с первого же — пару уже посмотрел живой модератор. Готовых таблиц в
проекте нет намеренно: выдуманная показывала бы людям чужую модель телефона.
Пока аппарат незнаком, бот так и пишет — «номер настоящий, модель пока не
определяется», а не молчит.

Узнанное по номеру мастер не переспрашивает: марка, модель и год
проставляются сами, бот показывает список заполненного и переходит сразу к
следующему неизвестному шагу — у продажи авто это пятый вместо второго.
Подставляется только то, что сошлось со справочником: марка «TOYOTA» из базы
находит «Toyota» в списке, а незнакомое название не проставляется вовсе.
Ответ человека сильнее подсказки: «Назад» и правка из предпросмотра
спрашивают поле заново.

Расхождения идут модератору вместе с карточкой: «указана Honda, по VIN —
TOYOTA», «по IMEI это Samsung Galaxy A54, а указана другая модель». Марку и
год сверяем, модель — нет: «Camry» против «Camry Hybrid» давало бы ложную
тревогу на каждом втором объявлении.

**Сделки.** Площадка не видит переписку — люди уходят в личку Telegram, — но
знает, когда разговор начался, и может спросить, чем он кончился. Нажали
«Связаться» — заводится сделка. Через два часа, при следующем заходе на то же
объявление, покупателю показывается вопрос «Вы договорились с <именем>?».
Ответил «да» — продавцу прилетает в бот кнопка «Сделка состоялась?». Подтвердил
и он — объявление снимается само: «Продано» у продажи, «Занято» у аренды, а
сделка попадает в счётчик. Любое «нет» оставляет объявление в каталоге.
Больше трёх раз вопрос не задаётся, свои объявления и посторонние
не считаются, ответить за другую сторону нельзя.

**Панель в боте** (`/panel`, кнопка «📊 Панель» у админов) — всё хозяйство
одним экраном: объявления по статусам и за сутки/неделю, люди и новые за
неделю, сделки (начато, состоялось, доля, ждут ответа продавца), размер
справочника моделей по IMEI, жалобы без ответа, пять популярных категорий.

**Аренда.** У категорий аренды статус «Занято» вместо «Продано»: объявление
скрывается из каталога и возвращается одной кнопкой «Снова свободно» —
без повторной подачи.

## Структура категорий

```
Недвижимость: аренда квартиры · продажа квартиры
Авто:         продажа · аренда · автоуслуги
Техника:      продажа техники · услуги ремонта
Запчасти(8):  авто · телефоны · компьютеры · бытовая техника
              · ТВ и аудио · инструмент · мото/вело · электроника
```

Справочники (`backend/app/seed/data/`): города Таджикистана с районами
Душанбе, бренды по 9 областям применения, модели автомобилей под местный
рынок. Пересборка: `tz/data/build_dictionaries.py` в корне репозитория.

## Проверено

- Юнит: VIN/IMEI/артикулы — контрольные суммы, эталонные значения.
- Интеграционно (реальные PostgreSQL + Redis): создание объявления из данных
  мастера, конвертация валют, повтор VIN → метка модератору, каталог,
  JSONB-фильтры, keyset-пагинация без дублей, избранное, жалобы (409),
  контакты, отказ поддельной initData, коды входа — 30 проверок.
- Лента: работа без данных, метки категорий, разнообразие, устойчивость
  порядка, пагинация без повторов, рост интересной категории в выдаче
  (с 5.6 позиции на 3.0) без исчезновения остальных — 10 проверок.
- Админ-панель: права доступа, очередь, одобрение и повторное одобрение (409),
  отклонение с причиной, жалобы, бан и разбан, запрет забанить себя,
  справочники, журнал — 31 проверка.
- Карта и вход: карта осталась ровно у двух категорий, координаты «некартовых»
  не отдаются, вход из Mini App заводит аккаунт сам, повтор не плодит дублей,
  смена имени подтягивается, поддельная подпись и свой вариант списка
  отклоняются — 16 проверок.
- Проверка номеров (двойник базы на localhost): расшифровка, кэш и
  отрицательный кэш, отказ сети и выключенная настройка, расхождения по марке
  и году, накопление справочника TAC, приоритет импорта над наблюдением,
  ручки для веб-формы — 28 проверок.
- Мастер с автозаполнением (настоящие обработчики, поддельные Bot и FSM):
  поля из VIN проставляются и пропускаются, номер кузова ничего не выдумывает,
  «Назад» спрашивает заново, ответ человека не перетирается, значение вне
  справочника и год вне диапазона отбрасываются — 18 проверок.
