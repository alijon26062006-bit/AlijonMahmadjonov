# ⭐ Stars Bot — бот для продажи Telegram Stars и Premium

Telegram-бот на **aiogram 3**: покупатель выбирает пакет, присылает `@username`
получателя и чек об оплате; после подтверждения админом звёзды или Premium
уходят получателю **автоматически** через Fragment.

## Как это работает

```
Покупатель                    Бот                      Админ            Fragment
    │                          │                         │                  │
    ├─ выбирает пакет ────────>│                         │                  │
    ├─ присылает @username ───>│── проверка получателя ──────────────────-─>│
    │<── реквизиты карты ──────┤                         │                  │
    ├─ присылает чек ─────────>│── заявка с кнопками ───>│                  │
    │                          │<── «Оплату вижу» ───────┤                  │
    │                          │── выдача ───────────────────────────-─────>│
    │<── «Заказ выполнен» ─────┤── отчёт ───────────────>│                  │
```

Пароль, код из SMS и доступ к аккаунту покупателя **не нужны** — Fragment
отправляет звёзды по публичному юзернейму.

## Запуск

```bash
cd stars_bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # и заполнить своими значениями
python -m app.main
```

### Что заполнить в `.env`

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | твой Telegram ID (узнать у [@userinfobot](https://t.me/userinfobot)), можно несколько через запятую |
| `ORDERS_CHAT_ID` | необязательно: чат/канал, куда дублируются заявки |
| `PAYMENT_CARD_NUMBER` / `PAYMENT_CARD_HOLDER` / `PAYMENT_BANK` | реквизиты для перевода |
| `CURRENCY` | валюта цен, по умолчанию `UZS` |
| `FRAGMENT_MODE` | `mock` для тестов, `api` для реальной выдачи |
| `FRAGMENT_API_KEY`, `FRAGMENT_PHONE_NUMBER`, `FRAGMENT_MNEMONICS` | доступы Fragment |

> ⚠️ **`.env` уже в `.gitignore` — никогда не коммить ключи и мнемонику.**
> Мнемоника из 24 слов = полный доступ к TON-кошельку. Если она где-то
> засветилась — сразу переводи средства на новый кошелёк.

### Цены

Лежат в [`prices.json`](prices.json). Файл перечитывается на каждый запрос —
менять цены можно **без перезапуска бота**.

```json
{ "stars": [{ "amount": 100, "price": 23000 }], "premium": [{ "months": 3, "price": 190000 }] }
```

## Режимы Fragment

| `FRAGMENT_MODE` | Поведение |
|---|---|
| `mock` | Ничего никуда не отправляет, пишет в лог и возвращает успех. Для отладки всего сценария без денег. |
| `api` | Реальные запросы к Fragment: авторизация по JWT, автоматическое переполучение протухшего токена. |

Пути эндпоинтов вынесены в константы в начале
[`app/services/fragment.py`](app/services/fragment.py). **Перед боевым запуском
сверь их со своей документацией Fragment** — если у тебя другие пути или формат
ответа, правится только этот файл, остальной код не трогается.

## Команды админа

| Команда | Что делает |
|---|---|
| `/admin` | список команд |
| `/pending` | заказы, ждущие проверки оплаты |
| `/orders` | последние 15 заказов |
| `/stats` | пользователи, выручка, разбивка по статусам |
| `/balance` | баланс кошелька Fragment |
| `/retry <id>` | повторить выдачу упавшего заказа |
| `/ban <user_id>` · `/unban <user_id>` | блокировка покупателя |

## Статусы заказа

`awaiting_receipt` → `pending_review` → `delivering` → `delivered`

Побочные ветки: `rejected` (админ не увидел оплату), `failed` (оплата принята,
но Fragment вернул ошибку — лечится `/retry`), `cancelled` (покупатель отменил
до отправки чека).

Переходы делаются одним `UPDATE ... WHERE status = ?`, поэтому если два админа
одновременно нажмут «Оплату вижу», выдача произойдёт ровно один раз.

## Структура

```
stars_bot/
├── app/
│   ├── main.py              точка входа, сборка диспетчера
│   ├── config.py            настройки из .env
│   ├── catalog.py           пакеты и цены из prices.json
│   ├── db.py                SQLite: пользователи, заказы, статусы
│   ├── keyboards.py         инлайн-клавиатуры
│   ├── texts.py             ВСЕ тексты бота — меняй стиль здесь
│   ├── states.py            FSM оформления заказа
│   ├── handlers/
│   │   ├── user.py          меню → выбор → получатель → оплата → чек
│   │   └── admin.py         подтверждение оплат, статистика, /retry
│   ├── services/
│   │   ├── fragment.py      клиент Fragment + mock-провайдер
│   │   └── delivery.py      выдача и уведомления
│   └── middlewares/
│       └── guard.py         регистрация пользователя, бан-лист
└── prices.json              цены
```

## Безопасность

- `.env`, база и виртуальное окружение — в `.gitignore`.
- Кошелёк Fragment держи с оборотным остатком, не со всеми деньгами.
- Ручное подтверждение оплаты — это и есть защита от фейковых чеков: сверяй
  сумму и время перевода в приложении банка, а не только картинку.
- Заказы отклонённых покупателей можно закрывать через `/ban`.
