# AVERIX — сайт студии

Сайт студии разработки: публичная часть, портфолио с кейсами, страница
студии, вакансии с откликами и собственная админка. Всё на одном сервере,
без внешних сервисов и без сборки фронтенда.

```
app/                    серверная часть (FastAPI)
  main.py               вход в админку, проекты, картинки, обработка ошибок
  routes_public.py      публичные страницы и формы
  routes_admin_studio.py  настройки, команда, вакансии, заявки, отклики
  routes_admin_work.py  специалисты, клиентские проекты, задачи, журнал
  routes_freelancer.py  кабинет специалиста
  adminkit.py           проверка входа админа, страницы ошибок
  render.py             шаблоны, язык, общий контекст страниц
  models.py             запросы публичной части
  work.py               запросы по специалистам, проектам и задачам
  security.py           пароли, сессии, CSRF, защита от перебора
  uploads.py            приём и обработка картинок
  notify.py             уведомления в базу и в Telegram
  audit.py              журнал действий администратора
  journal.py            журнал событий (без паролей и токенов)
  db.py / config.py     подключение к базе и настройки из окружения
  migrations/           нумерованные .sql, применяются при запуске
  templates/public/     страницы сайта
  templates/admin/      страницы админки
  templates/freelancer/ страницы кабинета
styles.css              все стили сайта (цвета меняются в :root)
app.js                  язык, меню, появление блоков, проверка форм
panel.js                подтверждения в админке
fonts.css + fonts/      Geologica, Golos Text, JetBrains Mono (woff2)
img/                    фотографии, лежащие в репозитории
tests/                  автотесты
deploy/                 установка и обновление на сервере
```

## Как это устроено

Статику (стили, скрипты, шрифты, картинки) отдаёт nginx прямо с диска.
Всё остальное — главная, проекты, кейсы, студия, вакансии, админка,
страницы ошибок — собирает приложение и берёт содержимое из базы.

Тексты первого экрана, контакты, цифры и вступления меняются в админке,
в разделе «Настройки», — без правки кода и без деплоя.

База (SQLite) и загруженные картинки лежат **вне репозитория**,
в `/var/www/averix-data`. Обновление делает `git reset --hard`, и всё,
что лежит в папке сайта, при обновлении заменяется версией из git.

## Запуск у себя

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt

export AVERIX_DATA_DIR=$PWD/data
export AVERIX_ALLOW_INSECURE=1     # разрешить вход по http, только локально
export AVERIX_SECURE_COOKIES=0

.venv/bin/python -m app.cli create-admin ваш-логин   # спросит пароль
.venv/bin/python -m uvicorn app.main:app --port 8001
```

Статику при таком запуске приложение не отдаёт — этим занимается nginx.
Для полноценного просмотра нужен nginx или любой статический сервер
поверх той же папки.

### Настройки из окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `AVERIX_DATA_DIR` | `/var/www/averix-data` | база и загруженные картинки |
| `AVERIX_SITE_URL` | `https://averix.dev` | адреса в canonical, og и sitemap |
| `AVERIX_SECURE_COOKIES` | `1` | флаг Secure у cookie сессии |
| `AVERIX_ALLOW_INSECURE` | `0` | разрешить вход по http (только разработка) |
| `AVERIX_DEBUG` | `0` | подробный журнал |
| `AVERIX_TELEGRAM_TOKEN` | пусто | токен бота для уведомлений |
| `AVERIX_TELEGRAM_CHAT` | пусто | куда слать уведомления |
| `AVERIX_SMTP_HOST` | пусто | почтовый сервер площадки |
| `AVERIX_SMTP_PORT` | `587` | порт почтового сервера |
| `AVERIX_SMTP_USER` | пусто | логин на почтовом сервере |
| `AVERIX_SMTP_PASSWORD` | пусто | пароль от почтового ящика |
| `AVERIX_SMTP_FROM` | пусто | адрес отправителя |
| `AVERIX_SMTP_TLS` | `1` | STARTTLS при отправке |

Telegram не обязателен: без этих двух переменных формы работают как
обычно, уведомления просто остаются в админке.

Почта нужна только площадке. **Без `AVERIX_SMTP_HOST` и
`AVERIX_SMTP_FROM` письма не уходят**, а значит не работают
подтверждение адреса и восстановление пароля: страница честно
сообщает об этом и предлагает написать в студию. Притворяться,
что письмо отправлено, приложение не будет.

Пароль администратора нигде в коде не лежит: он задаётся при создании
учётной записи и хранится только в виде scrypt-хеша.

## Тесты

```bash
.venv/bin/python -m pytest
```

Тесты работают во временной папке и никогда не трогают рабочую базу.
97 тестов. Проверяются: страницы, формы, спам-ловушка, язык, выдача
в поиске, вход админа и специалиста, права, CSRF, статусы заявок,
публикация проектов, приём картинок, весь ход задачи и разграничение
доступа — что специалист не видит и не двигает чужую задачу и не может
завершить свою.

Отдельно — учётные записи площадки: регистрация, повтор адреса,
слабый пароль, ограничение частоты, блокировка перебора, один и тот же
ответ на неизвестный адрес и на неверный пароль, одноразовость ссылок
из писем, закрытие всех сессий при смене пароля и отказ уводить
пользователя после входа на чужой сайт.

## Безопасность

| Что | Как сделано |
|---|---|
| Пароль | scrypt (n=2¹⁵, r=8), сравнение постоянное по времени |
| Сессия | токен в cookie HttpOnly + Secure + SameSite=Lax, в базе только его sha256 |
| CSRF | свой токен у каждой сессии, проверяется на всех формах |
| Перебор пароля | задержка после 3 неудач, блокировка после 5 за 15 минут |
| Загрузка картинок | проверка сигнатуры, распаковка Pillow, снятие EXIF, пережатие в WebP |
| Чужие картинки | операция проверяет, что картинка принадлежит этому проекту |
| Спам в формах | скрытое поле-ловушка + не больше трёх заявок с адреса за 10 минут |
| Заголовки | CSP без `unsafe-inline` для скриптов, nosniff, Referrer-Policy, X-Frame-Options |
| Журнал | пароли, токены и cookie в него не попадают — за этим следит `journal.py` |
| Ошибки | наружу уходит только «что-то сломалось», трассировка — в журнал сервера |
| Роли | у админа и специалиста разные таблицы сессий: общая однажды выдала бы чужой токен |
| Чужие задачи | владелец стоит в самом SQL-запросе, а не в проверке после выборки |
| Статика | с диска отдаётся только известный список файлов, а не всё, что лежит в репозитории |
| Журнал действий | кто и что менял — без паролей и токенов |

## Два языка

Русский текст лежит прямо в разметке — без JS сайт полностью читаем
и индексируется. Таджикский берётся из словаря `TG` в начале `app.js`
по ключам `data-i18n`, а содержимое из базы (проекты, вакансии,
настройки) — из полей `*_tj`. Если таджикское поле пустое, показывается
русское: машинного перевода нет намеренно.

Выбор языка пишется в cookie `averix-lang`, потому что подставлять
тексты из базы должен сервер.

> **Таджикский перевод нужно вычитать.** Он сделан не носителем языка.

## Роли и что каждая видит

| Роль | Вход | Видит |
|---|---|---|
| Посетитель | не нужен | сайт, формы заявки, отклика и анкеты |
| Администратор | `/admin` | всё: проекты, кейсы, команду, вакансии, заявки, специалистов, клиентские проекты, задачи, настройки, журнал |
| Специалист студии | `/freelancer/login` | только свои задачи и свою анкету |
| Пользователь площадки | `/freelance/login` | свой кабинет на AVERIX Freelance |

У каждой роли своя таблица сессий и своя cookie. Общая таблица на все
роли однажды выдала бы одной роли токен другой.

Специалист не видит ни других специалистов, ни чужие задачи, ни данные
заказчика, ни настройки. Проверка серверная: выборка по владельцу стоит
в самом SQL-запросе.

**Команда и фриланс — разные вещи.** Команда попадает на сайт,
специалисты из базы — никогда. Анкета сама учётную запись не создаёт:
доступ выдаёт админ после одобрения.

**Публичный кейс и клиентский проект — тоже разные.** В кейсе нет
бюджета и сроков, в клиентском проекте нет ничего, что можно показать
посетителю.

## AVERIX Freelance

Площадка живёт по адресу `/freelance` и от витрины отделена намеренно:
своя оболочка, своя навигация, только русский язык. Витрина двуязычная
и остаётся такой.

Одна учётная запись на человека (`users`), у неё до двух лиц: заказчик
(`client_profiles`) и специалист (строка в `freelancers` с заполненным
`user_id`). Второе лицо добавляется в кабинете одной кнопкой — второй
регистрации не нужно.

Анкета в закрытую базу студии никуда не делась: она переехала
на `/freelance/studio`, адрес формы `POST /freelance/apply` прежний.
Анкета по-прежнему не создаёт учётную запись и не попадает на сайт.

План работ и карты архитектуры — в `docs/freelance-plan.md`.

**Денежных расчётов площадка не проводит.** Настоящего платёжного
провайдера в проекте нет, поэтому слов «эскроу» и «средства защищены»
в интерфейсе нет тоже.

## Деплой на VPS

Первичная установка — один раз:

```bash
ssh root@IP-СЕРВЕРА
curl -fsSL "https://raw.githubusercontent.com/alijon26062006-bit/AlijonMahmadjonov/claude/ui-ux-pro-max-landing-n9y2jh/averix/deploy/setup.sh" -o setup.sh
less setup.sh          # прочитать перед запуском
bash setup.sh averix.dev
```

Скрипт ставит nginx, python, git и certbot, клонирует репозиторий
в `/var/www/averix-repo`, создаёт папку данных, поднимает службу
`averix` под systemd, настраивает nginx и выпускает сертификат.
Запускать можно повторно — уже настроенное он не ломает.

Обновление после каждого push:

```bash
bash /var/www/averix-repo/averix/deploy/update.sh
```

`update.sh` делает `git reset --hard`, поэтому **править файлы прямо
на сервере нельзя** — изменения будут стёрты. База и картинки лежат
вне репозитория и не затрагиваются.

### Про домен .dev

Зона `.dev` целиком входит в список HSTS preload, поэтому браузеры
отказываются открывать её по `http` — не «без замка», а вообще.
Пока certbot не выпустит сертификат, сайт не откроется. Если установка
упала на этом шаге, дело почти всегда в A-записи: она ещё не разошлась.

### Про кеш

Имена файлов не содержат хеша, поэтому `css` и `js` отдаются
с `Cache-Control: no-cache`: иначе после обновления вернувшийся
посетитель неделю видел бы старую версию. Это не отключает кеш,
а требует проверки — при неизменном файле сервер отвечает 304
в несколько байт. Шрифты закешированы на год, картинки на 30 дней.
