# Почта для площадки

Письма нужны площадке для двух вещей: подтвердить адрес при регистрации
и восстановить пароль. Больше ни для чего.

**Подтверждение ничего не запирает.** Регистрироваться, входить
и пользоваться площадкой можно и без него. Оно значит ровно одно: этот
адрес действительно принадлежит человеку, и письмо о смене пароля дойдёт
до него, а не до однофамильца с похожим адресом.

Без настроенной почты сайт работает как обычно — страница честно пишет,
что письмо не придёт, и предлагает написать в студию.

---

## Шаг 1. Пароль приложения Google

Обычный пароль от почты сюда не подходит: Google его не примет.
Нужен отдельный «пароль приложения» — он работает только для отправки
писем, и его можно отозвать, не меняя основной пароль.

1. Откройте <https://myaccount.google.com/security>
2. Включите **двухэтапную аутентификацию**, если она выключена.
   Без неё пункт с паролями приложений просто не появится.
3. Откройте <https://myaccount.google.com/apppasswords>
4. Придумайте название — например `AVERIX` — и создайте пароль.
5. Google покажет **16 символов с пробелами**. Это единственный раз,
   когда он их показывает: скопируйте сразу.

Пробелы внутри пароля можно оставить как есть.

## Шаг 2. Прописать на сервере

```bash
nano /etc/systemd/system/averix.service
```

В раздел `[Service]`, рядом с остальными строками `Environment=`,
добавьте пять:

```
Environment="AVERIX_SMTP_HOST=smtp.gmail.com"
Environment="AVERIX_SMTP_PORT=587"
Environment="AVERIX_SMTP_USER=ваш-адрес@gmail.com"
Environment="AVERIX_SMTP_PASSWORD=abcd efgh ijkl mnop"
Environment="AVERIX_SMTP_FROM=ваш-адрес@gmail.com"
```

**`FROM` обязан совпадать с `USER`.** Подставить туда
`noreply@averix.dev` не получится: Gmail не даёт отправлять от чужого
имени и отклонит письмо целиком. Красивый адрес отправителя — это
шаг «Дальше» в конце файла.

Применить:

```bash
systemctl daemon-reload
systemctl restart averix
systemctl is-active averix
```

## Шаг 3. Проверить

Зарегистрируйтесь на `/freelance/register` со своим настоящим адресом.
Письмо должно прийти в течение минуты, иногда во «Промоакции» или
«Спам» — в первый раз стоит заглянуть туда и отметить «не спам».

Если письма нет:

```bash
journalctl -u averix -n 50 --no-pager | grep письмо
```

| Что в журнале | Что это значит |
|---|---|
| `письмо.отправлено` | ушло; ищите в спаме |
| `письмо.не_доставлено причина=SMTPAuthenticationError` | не тот пароль: нужен пароль приложения, не обычный |
| `письмо.не_доставлено причина=TimeoutError` | хостер закрыл исходящий порт 587 — напишите в поддержку или переходите на почтовый сервис |
| ничего | переменные не подхватились: проверьте `systemctl show averix -p Environment` |

Ни пароль, ни адрес получателя целиком в журнал не попадают — за этим
следит `journal.py`.

## Дальше: свой адрес отправителя

Пока писем немного, Gmail справляется: лимит около 500 в сутки.
Когда площадка вырастет или письмо от личного gmail начнёт смущать,
переходите на почтовый сервис — **Resend** или **Brevo**, у обоих есть
бесплатный тариф на тысячи писем в месяц.

Что изменится: сервис даст записи **SPF** и **DKIM**, их нужно добавить
в DNS домена. Именно они разрешают отправлять письма от имени
`averix.dev`, без них такое письмо уходит в спам.

В `averix.service` меняются те же пять строк — например для Resend:

```
Environment="AVERIX_SMTP_HOST=smtp.resend.com"
Environment="AVERIX_SMTP_PORT=587"
Environment="AVERIX_SMTP_USER=resend"
Environment="AVERIX_SMTP_PASSWORD=ключ-от-сервиса"
Environment="AVERIX_SMTP_FROM=noreply@averix.dev"
```

Код при этом не меняется вовсе: приложение знает только, что есть
почтовый сервер, и не знает, чей он.
