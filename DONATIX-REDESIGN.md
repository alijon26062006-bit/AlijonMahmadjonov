## 2. Главное правило: меняем только внешний вид

Можно менять:
- шаблоны `donatix/templates/**` (разметка, классы), `donatix/static/**` (CSS, JS интерфейса, шрифты, картинки).

Нельзя менять (без отдельного «да» владельца):
- логику на Python (`donatix/*.py`), обработку денег, заказов, платежей, поставщиков, ботов;
- **адреса страниц и форм** (URL), **имена полей форм** (`name="…"`), CSRF-токены, скрытые поля,
  `id`/`data-*`, на которые опирается существующий JS;
- **структуру базы данных** (таблицы, колонки). Если без этого никак — только добавлять, никогда не удалять
  и не переименовывать, и сначала проверить на копии базы на бете.

Тексты, цены, товары, способы оплаты, разделы — **остаются как у Donatix**. Из нового дизайна берём
только внешний вид: раскладку блоков, цвета, шрифт, отступы, скругления, карточки, иконки, анимации.
Название везде **Donatix** (временное «Gemora» из демо не переносить).

## 3. Шаг 1 — резервная копия (ДО любых работ)

Агент даёт владельцу команды для сервера, владелец выполняет и присылает вывод.

```bash
sudo -iu donatix
mkdir -p ~/backup
# копия базы на ходу (безопасно, сайт не останавливать)
sqlite3 ~/app/donatix/data/donatix.db ".backup ~/backup/donatix-$(date +%F-%H%M).db"
# проверка копии
sqlite3 ~/backup/donatix-*.db "PRAGMA integrity_check;"      # должно быть: ok
sqlite3 ~/backup/donatix-*.db "select count(*) from users; select count(*) from orders;"
# настройки и загруженные файлы
cp ~/app/donatix/.env ~/backup/env-$(date +%F)
tar czf ~/backup/data-$(date +%F).tgz -C ~/app/donatix data
# запомнить версию кода, на которую можно вернуться
git -C ~/app rev-parse HEAD > ~/backup/version-before-redesign.txt
```
Скачать папку `~/backup` к себе на компьютер (или на другой сервер). **Без проверенной копии дальше не идти.**

## 4. Шаг 2 — бета-версия beta.donatix.tj

Бета — отдельная копия сайта на том же сервере: свой код (ветка `donatix-redesign`), своя копия базы,
свой порт. Настоящий сайт продолжает работать как раньше.

1. **DNS:** в Cloudflare (или у регистратора) добавить запись `A beta → IP сервера`.
2. **Код:** `git clone -b donatix-redesign <репозиторий> /home/donatix/beta` + своё окружение `.venv`.
3. **Копия базы:** `cp ~/backup/donatix-<дата>.db /home/donatix/beta/donatix/data/beta.db`.
4. **Свой `.env` для беты** (`/home/donatix/beta/donatix/.env`, на основе боевого), обязательно:
   - `DONATIX_DB` → `…/beta/donatix/data/beta.db` (**только копия!**);
   - адрес сайта → `https://beta.donatix.tj`;
   - **отключить всё, что трогает реальные деньги и людей** (названия переменных найти в `config.py`
     и `.env.example`):
     - ключи поставщиков (FazerCards и др.) — пустые → бета не может купить товар;
     - приём платежей (крипта, Bybit, SmartPay, банки, кассиры) — выключить;
     - **токены всех Telegram-ботов — пустые.** Два процесса с одним токеном ломают бота на боевом сайте;
     - почта, web-push, SMS — выключить;
     - **фоновый обработчик заказов** (worker, очереди поставщика, авто-возвраты) — выключить, иначе бета
       начнёт «доводить» копии настоящих заказов.
   Если чего-то нельзя выключить настройкой — сказать владельцу и **не запускать бету**, пока не решим.
5. **Служба `donatix-beta`:** копия `donatix.service` с `WorkingDirectory=/home/donatix/beta`
   и портом **8001**.
6. **Веб-сервер** (nginx или Caddy — посмотреть, какой стоит): `beta.donatix.tj → 127.0.0.1:8001`,
   HTTPS, **пароль на вход (basic auth)** и `X-Robots-Tag: noindex` — в копии базы настоящие клиенты,
   посторонние не должны видеть бету.
7. Проверить: настоящий donatix.tj работает как раньше, бета открывается только с паролем.

## 5. Шаг 3 — перенос дизайна (на ветке `donatix-redesign`, проверка на бете)

1. Составить таблицу: **страница Donatix → шаблон → экран нового дизайна** и показать владельцу.
   Ориентир экранов — раздел 4 файла `HANDOFF-DESIGN.md` (главная, вход, регистрация, кабинет, каталоги,
   страница товара, баланс и оплата, заказы, транзакции, статистика, профиль, настройки, поддержка).
2. Перенести **токены дизайна** (цвета, шрифт Inter, тени, скругления) в общий CSS Donatix.
3. Переделывать **по одному экрану**: сначала `base.html` (шапка, меню, подвал), потом главная, вход/регистрация,
   потом кабинет (`panel/`). **Админку (`admin/`) — в самом конце** и только если владелец попросит.
4. После каждого экрана:
   - `git push origin donatix-redesign` → на сервере обновить бету
     (`git -C /home/donatix/beta pull && sudo systemctl restart donatix-beta`);
   - скриншоты беты на телефоне **430 px и 360 px** и на компьютере **1440 px**;
   - сравнить с `shop-demo/screens/` и показать владельцу.
5. На бете пройти вручную: регистрация, вход, выход, каталог, страница товара, форма заказа (до оплаты),
   баланс и история, заказы, профиль, поддержка, админка открывается и показывает те же данные.
   **Реальные покупки на бете не делать** (поставщики там отключены).
6. Запустить тесты Donatix: `cd /home/donatix/beta && .venv/bin/python -m pytest donatix/tests -q` — всё зелёное.

Правила оформления (из `HANDOFF-DESIGN.md`, раздел 6): без логотипов правообладателей игр, без названия
поставщика, без слова «официальный», внизу дисклеймер «Независимый сервис, не связан с правообладателями игр».

## 6. Шаг 4 — выпуск на donatix.tj (только после «выпускаем» от владельца)

1. Выбрать спокойное время (мало заказов).
2. **Свежая резервная копия** (шаг 3 этой инструкции) прямо перед выпуском.
3. Влить `donatix-redesign` в `claude/website-api-sales-96wxcs` (merge, без переписывания истории) и отправить.
4. На сервере: `sudo bash /home/donatix/app/donatix/deploy/update.sh` — дождаться «✅ Готово».
5. Сразу проверить на настоящем сайте: главная, вход, кабинет, свой баланс и свои заказы на месте, админка,
   один тестовый заказ владельца на минимальную сумму.
6. **Откат, если что-то не так** (база не менялась, поэтому откат безопасен):
   ```bash
   sudo -u donatix git -C /home/donatix/app checkout $(cat /home/donatix/backup/version-before-redesign.txt)
   sudo systemctl restart donatix
   ```
   (после этого в ветке сделать `git revert` слияния, чтобы следующее обновление не вернуло дизайн).
7. Через несколько дней после успешного выпуска: удалить бету и **копию базы беты** (там личные данные клиентов),
   убрать DNS-запись `beta`.

## 7. Чего агент НЕ делает никогда

- не отправляет изменения в `claude/website-api-sales-96wxcs` без «выпускаем» от владельца;
- не запускает на бете ничего, что может списать деньги, купить товар, написать клиентам или ответить ботом;
- не удаляет и не переименовывает таблицы/колонки базы, не чистит данные;
- не меняет `.env` боевого сайта (кроме того, что владелец сам попросит);
- не просит ключи и пароли в чат — только владелец вписывает их на сервере;
- не переносит `shop-backend/` и его базу на donatix.tj.

## 8. Что может понадобиться от владельца

- выполнить на сервере команды, которые даст агент, и прислать вывод (или подключить сервер к сеансу);
- добавить DNS-запись `beta` в Cloudflare;
- скриншоты страниц Donatix, если агенту что-то непонятно;
- «да» перед каждым большим шагом и «выпускаем» перед выпуском.
