# Бэкенд The Burger

Сервер сайта: меню в базе, админка для заведения, приём заказов.
Ставится на любой недорогой VPS, тяжёлого ничего не нужно.

- **API для сайта** — `/api/menu`, `/api/orders`
- **Админка** — `/admin`: блюда, цены, фото, наличие, заказы, настройки
- **База** — SQLite, один файл `data/burger.db`
- **Уведомления** — заказ приходит в Telegram, если настроен бот

Цены и суммы считает сервер. Данные из браузера для этого не используются:
их можно подделать.

## Установка на сервер одной командой

На чистом VPS с Ubuntu или Debian:

```bash
curl -fsSL https://raw.githubusercontent.com/alijon26062006-bit/AlijonMahmadjonov/claude/phone-store-frontend-design-fzwpi1/burger/backend/deploy.sh | sudo bash -s -- theburger.tj
```

Скрипт ставит Python и Caddy, забирает код, создаёт службу systemd, придумывает
пароль админки, настраивает домен с бесплатным HTTPS, включает ежедневную копию
базы, спрашивает токен бота и сам включает вебхук курьеров.

Токен можно передать и сразу, третьим и четвёртым словом — тогда вопросов не
будет вовсе:

```bash
... | sudo bash -s -- theburger.tj 123456:ABC-токен 987654321
```

Домен должен заранее смотреть A-записью на этот сервер — Caddy получает
сертификат сам, но только если домен до него доходит.

Скрипт можно запускать сколько угодно раз: он обновляет код и настройки, а базу
и пароль не трогает.

Если установка сорвалась на полпути и хочется начать с чистого листа — добавьте
`--clean`. Служба, папка и расписание копий сносятся, база перед этим уезжает
в `/srv/backup`:

```bash
... | bash -s -- theburger.tj --clean
```

## Запуск на своей машине

```bash
cd burger/backend
./run.sh
```

Скрипт сам создаст окружение, поставит зависимости и запустит сервер.

- сайт-API: http://127.0.0.1:8000/api/menu
- админка: http://127.0.0.1:8000/admin

При первом запуске база наполняется меню из `seed_data.py` — 25 блюд,
5 разделов, районы доставки. Дальше всё правится в админке.

## Подключить сайт к серверу

В `burger/js/main.js` первая настройка:

```js
const API = 'auto';   // сервер на том же домене, что и сайт
```

- `'auto'` — так на боевом домене: Caddy отдаёт сайт файлами, а `/api`, `/admin`,
  `/kitchen` и `/courier` уводит на Python.
- `''` — сервера нет: встроенное меню, заказ уходит текстом в Telegram.
- `'https://api.theburger.tj'` — бэкенд на отдельном домене.

Сайт смотрит не на настройку, а на живой ответ сервера. Не ответил — молча
показывает встроенное меню и отправляет заказ в Telegram: пустой страницы
клиент не увидит.

## Панель кухни

Отдельный экран `/kitchen` для планшета на кухне. Вход тот же, что в админку —
на планшете достаточно войти один раз, дальше он помнит вход неделю.

- крупные тикеты: номер, доставка или самовывоз, минуты с момента заказа
- состав с количеством и пометками вроде «без лука» жёлтым
- комментарий клиента отдельным блоком
- две кнопки: «Взять в работу» и «Готово». Выданный заказ уходит с экрана
- через 20 минут рамка и таймер краснеют
- список сам обновляется каждые 5 секунд
- на новый заказ — три громких гудка в две ноты (880 и 1320 Гц, квадратная
  волна): такой сигнал пробивается сквозь шум вытяжки лучше чистого тона
- пока заказ не взяли в работу, сигнал повторяется каждые 15 секунд
- звук выключается кнопкой, выбор запоминается
- браузеры не дают звук до первого касания экрана — панель честно пишет
  об этом жёлтой кнопкой, одно нажатие включает сигнал
- цен на экране нет: кухне они не нужны

## Курьеры

Курьер работает из Telegram: заказ приходит ему в чат кнопкой, а по ссылке
открывается панель `/courier` — тот же список, но со всеми подробностями.

Как записывается курьер:

1. Жмёт «Старт» у бота.
2. Бот просит номер — одной кнопкой «Отправить мой номер». Набранный руками
   номер не принимается: так в базу попадает только его собственный.
3. Бот просит имя — его увидит кухня.
4. Заявка уходит хозяину в Telegram с кнопками «Допустить» и «Отказать»
   и появляется на странице `/admin/couriers`.
5. После допуска курьеру приходит кнопка «Открыть панель», и заказы идут в чат.

Со стороны сервера нужно один раз: заполнить `TG_TOKEN` в `.env`
(`PUBLIC_URL` и `TG_HOOK_SECRET` ставит `deploy.sh`) и включить вебхук —
`.venv/bin/python hook.py on`.

Дальше всё идёт само:

- кухня отмечает заказ готовым — бот пишет всем курьерам на смене
- кто первый нажал «Беру заказ», тому он и достаётся; у остальных сообщение
  переписывается на «Заказ уже забрал такой-то»
- взявший видит адрес, имя и телефон клиента, кнопку «Доставил»
- пока заказ никто не взял, бот напоминает каждые две минуты (до пяти раз):
  одно письмо со всеми свободными заказами, кнопка на каждый и «Открыть панель»
- курьер может вернуть заказ («не смогу») — он тут же уходит обратно всем
- панель `/courier` обновляется каждые 7 секунд и звенит на новый заказ
- ссылка на панель личная и подписанная: чужая или подделанная не откроется
- «Снять со смены» на `/admin/couriers` — заказы этому курьеру больше не идут

Заказ забирается одним запросом к базе (`UPDATE ... WHERE courier_id = ''`),
поэтому двум курьерам один и тот же заказ не достанется, даже если они нажали
кнопку одновременно.

## Панели внутри Telegram

Хозяин и курьеры не ходят по ссылкам и не помнят паролей: панель открывается
прямо в Telegram как приложение (Mini App).

Ботов два, и это намеренно: у хозяина свой вход, у курьеров свой, и токен
одного не открывает чужую панель.

| Бот | Кнопка | Куда ведёт |
|-----|--------|------------|
| админки (`TG_ADMIN_TOKEN`) | «📊 Открыть админку» | `/admin` — заказы, меню, кухня, курьеры, отчёт |
| курьеров (`TG_TOKEN`) | «🛵 Открыть панель» | `/courier` — свободные и свои заказы |

Кто вошёл, проверяет сервер: Telegram передаёт странице подписанную строку,
подпись сходится только с токеном нужного бота (`webapp.py`). Дальше:
в админку пускаем только id из `ADMIN_TG_IDS`, в панель курьера — только
допущенного курьера. Пароль остаётся запасным входом с компьютера.

Внутри Telegram панель ведёт себя как приложение: своя шапка скрыта — её
рисует Telegram, работает системная кнопка «назад», нажатия отзываются
вибрацией, цвет полос совпадает с фоном.

## Панели на телефоне

Четыре рабочих экрана, все рассчитаны на телефон в руке, а не на мышку:

| Экран | Кто смотрит | Что умеет |
|-------|-------------|-----------|
| `/admin` | хозяин | заказы, одна большая кнопка «следующий шаг», остальные статусы под «Другой статус» |
| `/admin/menu` | хозяин | 94 блюда, поиск по названию, разделы сворачиваются и запоминаются |
| `/kitchen` | кухня | тикеты, звук, обновление раз в 5 секунд, красная полоса при потере связи |
| `/courier` | курьер | свободные и свои заказы, «Беру» и «Доставил», звонок клиенту |

Общее: разделы админки внизу экрана, под большим пальцем; всё нажимаемое
не меньше 44 точек; оболочка панелей лежит в кэше, поэтому экран поднимается
и на моргающем wi-fi — а заказы всегда берутся живьём с сервера.

Кухня и курьер ставятся на устройство как приложение: у каждой панели свой
манифест и своя иконка.

## Оплата переводом

Клиент может заплатить наличными курьеру или переводом в банк. Реквизиты
хозяин заполняет сам на странице `/admin/banks`: название, имя и фамилия
получателя, номер карты. Пока имя и номер пустые, банк клиенту не показывается —
иначе он увидит пустые реквизиты и не поймёт, куда платить.

Как это идёт у клиента:

1. Собрал заказ, вписал имя, телефон и адрес → «Подтвердить заказ».
2. Экран оплаты: наличными курьеру или один из банков.
3. Выбрал банк → видит имя получателя и номер карты, кнопка «Копировать»,
   и место, куда приложить чек — фото перевода или PDF.
4. Отправил чек → заказ уходит хозяину на проверку.

Дальше по цепочке: хозяин смотрит чек в админке и жмёт «Оплата пришла — на
кухню», заказ появляется на кухне, кухня жмёт «Готово», заказ уходит курьерам.

Заказ переводом не попадает на кухню, пока оплату не подтвердили: до чека он
в состоянии «ждём чек», после — «проверить чек». Реквизиты не лежат в общем
меню: клиент получает их вместе с номером своего заказа. Пропуск на загрузку
чека подписан и живёт два часа, повторно тот же чек не принимается.

## Отчёт

`/admin/stats` — сводка за любой период: даты выбираются вручную, рядом кнопки
«Сегодня», «7 дней», «30 дней», «Этот месяц».

Показывает выручку, число заказов, средний чек и среднее за день; разбивку по
дням и часам, доставку против самовывоза, что берут чаще, районы и курьеров.
Отменённые заказы в выручку не идут и считаются отдельно.

Время считается душанбинское (+5): заказ в час ночи попадает во вчерашнюю
смену, а не в позавчерашнюю. Смещение меняется переменной `TZ_HOURS`.

## Что сделано ради надёжности

Разбор всего проекта на «где упадёт» и «где пролезут». Найденное и закрытое:

**Данные и деньги**
- чеки об оплате лежали в открытой папке `uploads` — их мог открыть любой,
  кто угадает имя файла. Переехали в `receipts/`, отдаются только хозяину
  через `/admin/receipt/{имя}`, имя проверяется по образцу
- тип файла брался со слов браузера — теперь смотрим первые байты самого файла:
  страница, переименованная в `.jpg`, не пройдёт
- номер заказа считался как `MAX(number)+1` отдельным запросом: два заказа
  в одну секунду получали одинаковый номер. Теперь номер выдаётся тем же
  INSERT, проверено тридцатью одновременными заказами

**Нападения**
- комментарий клиента вставлялся в панель кухни как есть: строка вида
  `<img onerror=...>` выполнилась бы на планшете, вошедшем в админку. Всё
  чужое теперь экранируется — и на кухне, и на сайте
- куки живут с `SameSite=None` ради Telegram, значит чужой сайт мог тихо
  дёрнуть админку от имени хозяина. У изменяющих запросов сверяется источник
- пароль подбирался перебором без ограничений — после восьми промахов адрес
  отдыхает 15 минут
- поля заказа не имели потолка: можно было прислать мегабайт текста
- заголовки `nosniff` и `Referrer-Policy` на каждом ответе, ограничение
  размера запроса в Caddy

**Падения**
- SQLite работал без WAL и без ожидания блокировки: кухня опрашивает сервер
  каждые 5 секунд, курьеры каждые 7, и заказ в этот момент получал
  «database is locked». Включены WAL и ожидание до 15 секунд
- корзина с блюдом, которое убрали из меню, роняла страницу целиком —
  теперь такие строки тихо убираются с понятным сообщением
- испорченная корзина в памяти телефона роняла весь скрипт — обёрнуто
- списки адресов для защиты от частых заказов росли вечно — чистятся
- `sqlite3` не ставился, и ежедневная копия базы молча не делалась
- копии теперь сжимаются, хранятся 30 дней, чеки копируются рядом

**Сторож**
`watchdog.sh` раз в пять минут проверяет, что сервер отвечает, что на диске
есть место и что база цела. Сервер молчит — поднимает его сам и пишет хозяину
в Telegram. Поднялся — сообщает, что всё в порядке.

## Настройки

Задаются переменными окружения (файл `.env` или systemd).

| Переменная | Зачем |
|------------|-------|
| `ADMIN_PASSWORD` | пароль в админку. **Обязательно смените** |
| `SECRET_KEY` | подпись входа. Длинная случайная строка |
| `TG_TOKEN` | токен бота у @BotFather — чтобы заказы падали в Telegram |
| `TG_ADMIN_CHAT` | куда слать: ваш id у @userinfobot или id группы |
| `PUBLIC_URL` | адрес сайта снаружи: ссылка на панель курьера и вебхук |
| `TG_HOOK_SECRET` | секретный кусок адреса, куда Telegram шлёт нажатия |
| `ALLOWED_ORIGINS` | адреса сайта через запятую. На бою укажите свой домен вместо `*` |
| `TZ_HOURS` | часовой пояс заведения, по умолчанию 5 (Душанбе) |
| `ORDER_COOLDOWN` | секунд между заказами с одного адреса, по умолчанию 20 |

## На сервере

Пример для Ubuntu: systemd + Caddy для HTTPS.

`/etc/systemd/system/burger.service`:

```ini
[Unit]
Description=The Burger
After=network.target

[Service]
WorkingDirectory=/srv/burger/backend
EnvironmentFile=/srv/burger/backend/.env
ExecStart=/usr/bin/python3 -m uvicorn app:app --host 127.0.0.1 --port 8000
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now burger
```

`Caddyfile` — HTTPS оформляется сам:

```
api.theburger.tj {
    reverse_proxy 127.0.0.1:8000
}
```

## Резервная копия

Вся база — один файл. Копировать раз в сутки:

```bash
sqlite3 /srv/burger/backend/data/burger.db ".backup /srv/backup/burger-$(date +%F).db"
```

Фото лежат в `uploads/` — их тоже в копию.

## Проверки

```bash
python3 -m pytest tests/ -q
```

14 проверок: подсчёт цены на сервере, доставка по районам, бесплатная
доставка от порога, минимальный заказ, отказ по несуществующему блюду,
защита админки, вход с кириллическим паролем, скрытие блюда из наличия.
