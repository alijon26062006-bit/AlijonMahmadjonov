ID товаров

Каждый товар и каждый пакет имеет свой product_id — его вы передаёте в POST /orders. По виду ID сразу понятно, что это за товар:

Товарproduct_idПример
Пополнения игр (FF, PUBG Mobile и др.)topup- + 10 знаковtopup-3f9a1c2b7d
Подарочные картыgc- + 10 знаковgc-8b21e0d4a6
Ключи игрgk- + 10 знаковgk-5c0f7a9e13
Telegram Starsпостоянныйtg-stars
Telegram Premiumпо сроку, в месяцахtg-premium-3 tg-premium-6 tg-premium-12
Пополнение Steamпостоянныйsteam-topup

Примеры topup-… выше — условные. У каждой игры и каждого пакета (100 алмазов, 310 алмазов, недельный ваучер…) свой ID; настоящие берите из GET /products. ID не меняется, пока пакет есть в продаже, — его можно сохранить у себя и не запрашивать каталог перед каждым заказом.

1Найти игру

curl -s "{{ base_url }}/api/v1/categories" -H "X-API-Key: $KEY"

В ответе у каждой игры есть category_id — по нему удобно брать только её пакеты.

2Получить пакеты и их ID

curl -s "{{ base_url }}/api/v1/products?kind=topup&q=free%20fire" -H "X-API-Key: $KEY"

Картинки: у каждого товара и каждой игры есть поле image_url — полная ссылка на картинку на donatix.tj. Если картинки ещё нет, поле равно null.

За один запрос отдаётся не больше limit товаров: по умолчанию 100, максимум 500. Если пакетов больше, листайте через offset: ?limit=500&offset=0, потом offset=500 и так, пока items не станет пустым. Так вы получите все товары, а не только первую сотню.

for off in 0 500 1000 1500 2000; do
  curl -s "{{ base_url }}/api/v1/products?kind=topup&limit=500&offset=$off" -H "X-API-Key: $KEY"
done
{"ok": true, "items": [{
  "product_id": "topup-3f9a1c2b7d",
  "kind": "topup", "category_id": "free_fire", "category_name": "FF",
  "region": "CIS", "region_title": "СНГ",
  "name": "100 Diamonds", "title": "100 алмазов", "emoji": "💎",
  "price_usd": "0.9900",
  "fields": [{"key": "player_id", "label": "ID игрока", "type": "text"}]
}]}

Смотрите на region: у одной игры бывают пакеты для разных регионов (например, FF СНГ и Индонезия) — у них разные ID, и пакет другого региона на аккаунт не зачислится.

3Заказать пакет по его ID

curl -s -X POST {{ base_url }}/api/v1/orders \
  -H "X-API-Key: $KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{"product_id": "topup-3f9a1c2b7d", "fields": {"player_id": "1234567890"}}'
Бот в формате API v2. Там пакет передаётся как offer_id — в него ставится тот же product_id (topup-…), а в category_id — category_id игры: POST /api/v2/topups/order с телом {"category_id": "free_fire", "offer_id": "topup-3f9a1c2b7d", "fields": {"player_id": "1234567890"}}. Список пакетов в этом формате — GET /api/v2/topups/offers?category_id=….

Проверка аккаунта

Для многих игр можно проверить ID до заказа и показать покупателю ник. Заказ на несуществующий аккаунт не создаётся, деньги не списываются.

curl -s -X POST {{ base_url }}/api/v1/accounts/check \
  -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"product_id": "topup-a1b2c3d4e5", "fields": {"player_id": "5123456789"}}'
{"ok": true, "supported": true, "valid": true, "player_name": "Player_6789", "region": "GLOBAL"}

Пополнение баланса

Деньги за заказы списываются с вашего баланса в {{ site_name }}. Пополнить его можно в кабинете или через API:

1Заявка

curl -X POST {{ base_url }}/api/v1/payments -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"method": "dc", "amount_tjs": "200"}'

В ответе — реквизиты (номер карты/телефона) и точная сумма к переводу.

2Перевод и чек

Переведите ровно эту сумму на указанные реквизиты и пришлите чек: POST /payments/{id}/receipt (multipart, поле file). Статус — GET /payments/{id}.

«Душанбе Сити»: приложение → «Переводы» → «По номеру карты» → вставьте номер карты из ответа.

Виртуальные номера (коды из SMS)

Номер на один СМС-код: вы покупаете номер для сервиса, получаете код и отдаёте его клиенту. Цены как на сайте. Деньги списываются с баланса аккаунта ключа. Если номер не получился или код не пришёл за отведённое время, деньги возвращаются на баланс сами.

curl -s "{{ base_url }}/api/v1/numbers/services" -H "X-API-Key: $KEY"
{"ok": true, "items": [{"service": "telegram", "title": "Telegram"}, {"service": "whatsapp", "title": "WhatsApp"}]}
curl -s "{{ base_url }}/api/v1/numbers/countries?service=telegram" -H "X-API-Key: $KEY"
{"ok": true, "items": [{"country": "indonesia", "title": "Индонезия", "flag": "🇮🇩", "price_usd": "0.3100", "available": 120}]}
curl -s -X POST "{{ base_url }}/api/v1/numbers/orders" -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"service": "telegram", "country": "indonesia"}'
{"ok": true, "order": {"id": 555, "service": "telegram", "country": "indonesia", "status": "PENDING", "phone": "+6281234567", "code": null, "sms": null, "price_usd": "0.3100", "expires": "2030-01-01T00:15:00Z", "refunded": false}}
curl -s "{{ base_url }}/api/v1/numbers/orders/555" -H "X-API-Key: $KEY"

Когда в code появится код, номер готов. Статусы: PENDING — ждём код, RECEIVED — код пришёл, FINISHED — завершён, CANCELED — отменён, TIMEOUT — код не пришёл, деньги вернулись, BANNED — номер отклонён сервисом, деньги вернулись.

curl -s -X POST "{{ base_url }}/api/v1/numbers/orders/555/cancel" -H "X-API-Key: $KEY"

Список своих заказов: GET /api/v1/numbers/orders?limit=20. Ошибки: insufficient_balance (402) — пополните баланс; order_failed (400) — номер не купился, деньги не списаны; service_unavailable (503) — сервис временно выключен.

Подарки Telegram

Подарок за Telegram Stars, который уходит на аккаунт получателя. Цена как на сайте, списание с баланса. Если знаете @username получателя и он уже нажимал Start в нашем боте, подарок уходит сразу. Если нет, создаётся ссылка: отправьте её получателю, он нажмёт Start и получит подарок.

curl -s "{{ base_url }}/api/v1/gifts" -H "X-API-Key: $KEY"
{"ok": true, "items": [{"gift_id": "g15", "stars": 15, "emoji": "🧸", "image": null, "price_usd": "0.2400", "left": null, "total": null}]}
curl -s -X POST "{{ base_url }}/api/v1/gifts/orders" -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"gift_id": "g15", "recipient": "@username", "text": "С днём рождения!"}'
{"ok": true, "order": {"id": 91, "ref": "GF-91", "gift_id": "g15", "stars": 15, "price_usd": "0.2400", "status": "paid", "recipient": "@username", "link": null, "error": null}}
curl -s "{{ base_url }}/api/v1/gifts/orders/91" -H "X-API-Key: $KEY"

Если получатель ещё не нажимал Start, в ответе будет "status": "awaiting_recipient" и поле link: отправьте её получателю. Статусы: paid — в очереди, sent — отправлен, awaiting_recipient — ждём получателя, failed и refunded — деньги вернулись. Поле text — до 128 символов, подпись к подарку.

Правила и ответственность

  1. Данные получателя вводит покупатель. ID игрока, сервер, Telegram-username, Steam-логин, ссылка обмена, ID клана — {{ site_name }} отправляет товар ровно туда, куда указано. Если заказ выполнен на неверно введённый ID или username — деньги не возвращаются и товар не переносится. Перед заказом проверяйте аккаунт (POST /accounts/check или /api/v2/topups/validate-id) и показывайте покупателю ник.
  2. Оплата — только на реквизиты из ответа POST /payments (или со страницы «Пополнить»). Перевод на другую карту или номер, не ту сумму или по старым реквизитам {{ site_name }} не получает и не зачисляет. Реквизиты копируйте кнопкой, не вручную.
  3. Возврат — автоматически, если заказ не выполнен (статус failed): деньги сразу на баланс. Выполненные заказы, аренда номеров и запущенные боты для гильдии не возвращаются.
  4. Ключ — как пароль. Не публикуйте его, не вставляйте в сайт или приложение, которое видят покупатели, — только на сервере. Утёк — сразу отзовите в кабинете → API и создайте новый. За заказы по вашему ключу отвечаете вы.
  5. Нельзя: подбирать ключи и ID, обходить лимиты, слать заведомо неверные данные массово, перепродавать доступ к ключу. За это ключ и аккаунт блокируются.
  6. Цены в API — уже с вашей наценкой уровня (bronze/silver/gold). Цена фиксируется в момент заказа.
  7. Вопросы и спорные заказы — в поддержку (кабинет → «Поддержка»), с номером заказа dx-….

Webhook

Адрес указывается в панели → API. При смене статуса заказа придёт:

POST https://your-site.com/donatix-hook
X-Donatix-Timestamp: 1767225600
X-Donatix-Signature: 5d41402abc4b2a76b9719d911017c592

{"event": "order.updated", "order": {"order_id": "dx-1042", "status": "completed"}}

Подпись — HMAC-SHA256 от timestamp + "." + тело вашим секретом. Ответьте 2xx, иначе повторим до 5 раз.

import hmac, hashlib

def valid(secret: str, timestamp: str, body: bytes, signature: str) -> bool:
    mac = hmac.new(secret.encode(), timestamp.encode() + b"." + body, hashlib.sha256)
    return hmac.compare_digest(mac.hexdigest(), signature)

def buy_stars(username: str, amount: int) -> dict:

                            "fields": {"telegram_username": username}}, timeout=30)
    data = r.json()
    if not data["ok"]:
        raise RuntimeError(data["error"])
    return data["order"]

});
const data = await res.json();
