# Ревизия: сканер ценников

Подсчёт товара на ревизии телефоном. Камера включена всё время: сотрудник подносит
бирку в рамку, сканер сам её снимает, Claude читает цену, и она прибавляется к сумме.

Работает как мини-апп в Telegram: у каждого сотрудника свой счёт, админ видит всех
и общую сумму. Фото не сохраняются, в базе только цифра, время и кто сканировал.

## Установка на свой сервер

Нужен сервер с Ubuntu или Debian, свободные порты 80 и 443, токен нового бота
от @BotFather и ключ Anthropic.

```bash
git pull
bash setup_reviziya.sh
```

Скрипт ставит библиотеки, спрашивает токен и ключ, подбирает бесплатный адрес
вида `reviziya.1-2-3-4.sslip.io`, ставит Caddy (он сам получает сертификат HTTPS)
и запускает сервис `reviziya`. Кнопку «Сканер» в меню бота сервер ставит сам.

После установки:

1. Открой бота и нажми /start, потом «Открыть сканер». Первый, кто откроет, становится админом.
2. Сотрудники открывают того же бота. Админу приходит сообщение с кнопками «Допустить» и «Отклонить».
3. Вкладка «Админ»: общая сумма, кто сколько насчитал, отчёт в Excel (приходит файлом в чат), новая ревизия.

Обновление: `git pull && sudo systemctl restart reviziya`. Логи: `journalctl -u reviziya -f`.

## Как это устроено

- `reviziya/` — страница мини-аппа: `index.html` (экран), `app.js` (камера, автоснимок, счёт),
  `vendor/anthropic-sdk.js` (библиотека `@anthropic-ai/sdk` 1.14.0 для режима проверки).
- `reviziya_server/` — сервер на Python:
  - `app.py` — запросы мини-аппа;
  - `tgauth.py` — проверка подписи Telegram, по ней сервер узнаёт сотрудника;
  - `reader.py` — чтение цены через Claude;
  - `db.py` — база SQLite в `data/reviziya.db`;
  - `bot.py` — бот: кнопка, заявки сотрудников, отправка отчёта;
  - `report.py` — отчёт в Excel;
  - `check.py` — проверка ключей при установке.
- `setup_reviziya.sh` — установщик.
- `tests/test_reviziya.py` — тесты сервера.

Автоснимок: область рамки несколько раз в секунду сжимается в маленькую серую картинку.
Когда соседние картинки почти не отличаются, бирка считается неподвижной и уходит один кадр.
После этого сканер ждёт, пока картинка сильно изменится (бирку убрали), и только тогда
готов снимать следующую. Так одна бирка не считается дважды.

Умный зум:

- сканер ищет в рамке саму бирку (светлое пятно без цвета) и обводит её зелёной рамкой;
- на чтение уходит не вся рамка, а бирка, вырезанная крупно в полном разрешении камеры;
- из трёх кадров подряд берётся самый чёткий;
- если бирка маленькая и телефон даёт управлять зумом камеры, сканер сам приближает и потом возвращает обзор;
- кнопки 1×, 2×, 3× и два пальца задают приближение вручную.

Ключ Anthropic лежит только на сервере, в файле `.env.reviziya`. В телефоны он не попадает.

Настройки в `.env.reviziya`:

| Переменная | Что это |
|---|---|
| `REVIZIYA_BOT_TOKEN` | токен бота |
| `ANTHROPIC_API_KEY` | ключ Anthropic |
| `REVIZIYA_URL` | адрес мини-аппа, `https://…` |
| `REVIZIYA_MODEL` | модель, по умолчанию `claude-haiku-5-5`; точнее, но медленнее: `claude-sonnet-5-5` |
| `REVIZIYA_ADMIN_IDS` | id тех, кто сразу становится админом (необязательно) |

## Режим проверки без сервера

Если открыть страницу в обычном браузере, она работает сама по себе: ключ Anthropic
вводится во вкладке «Настройки» и хранится в этом телефоне, счёт тоже. Сотрудникам
так давать нельзя, это только для проверки скорости и точности.

`?debug=1` в адресе показывает числа детектора на экране, чтобы подстроить пороги.

## Что проверено

- Тесты сервера: вход через Telegram, счёт, права, заявки, отчёт (Claude подменён).
- Сквозной прогон в Chromium с искусственной камерой и подменённым Claude: админ, заявка
  сотрудника, допуск, сканы, минус, отмена, отчёт.
- Установщик прогнан с заглушками вместо systemd, Caddy и сети.

Не проверено: настоящий сервер, настоящий Telegram, настоящий ответ Claude и настоящий телефон.
