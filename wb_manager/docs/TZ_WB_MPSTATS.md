# Техническое задание: AI-менеджер для продавцов Wildberries (WB + MPStats)

Версия 2.0 от 14.10.2026 · Заказчик: Алижон · Статус: проект для согласования

## 1. Общие сведения

**Продукт.** Telegram-бот «AI-менеджер», который анализирует магазин продавца на Wildberries и рынок вокруг него, находит проблемы и точки роста и объясняет простым языком, что делать.

**Ценность для продавца.** Меньше потерянных продаж (товар закончился, упали позиции, реклама сжигает бюджет), меньше лишних расходов (штрафы, логистика, хранение, убыточные товары) и понимание, где он проигрывает конкурентам.

**Целевая аудитория.** Продавцы WB любого размера, работающие по схемам FBW, FBS, DBW, DBS. Основной канал — телефон.

**Источники данных:**

| Источник | Что даёт | Доступ |
| --- | --- | --- |
| Wildberries API (официальный) | данные **своего** магазина: заказы, продажи, остатки, отзывы, реклама, финансы, карточки | токен WB продавца, только чтение |
| MPStats API | данные **рынка**: конкуренты, их цены и продажи (оценка), ниши, позиции в поиске | токен MPStats (подписка) |
| Файл продавца | себестоимость товаров | CSV/Excel в чат бота |
| Claude (Anthropic) | понятный текст отчёта по готовым цифрам | ключ сервиса |

**Термины.** *Проверка* — модуль, который ищет один вид проблемы. *Находка* — найденная проблема с важностью, цифрами, причиной и рекомендацией. *Анализ* — запуск всех проверок по магазину.

## 2. Принципы (обязательны для всех версий)

1. **Только официальные источники данных.** Данные WB — только через официальный WB API; данные рынка — только через официальный API MPStats. Сбор данных с сайта WB программами-парсерами не используется.
2. **Чтение отдельно от управления.** Анализ работает с токеном «Только чтение». Функции управления — отдельные модули с отдельным токеном и подтверждением каждого действия.
3. **Цифры считает код, а не ИИ.** Расчёты детерминированные, пороги настраиваются. Claude только пересказывает готовые цифры; число, которого нет в данных, автоматически отбрасывается.
4. **Честность данных.** Нет данных — проверка помечается «нет данных». Данные похожи на сбой — в отчёте предупреждение. Оценки рынка (MPStats) всегда помечены как оценки.
5. **Безопасность.** Токены шифруются, в логи не попадают, каждый продавец видит только свои магазины.

| --- | --- | --- |

## 4. Пользовательские сценарии (Telegram-бот)

1. **Регистрация.** /start → кнопка «Поделиться номером» (номер подтверждён Telegram) → согласие на обработку персональных данных.
2. **Подключение магазина WB.** Продавец присылает токен → бот сразу удаляет сообщение → проверяет доступ к разделам WB → сохраняет токен в зашифрованном виде → показывает, какие разделы доступны.
3. **Подключение MPStats (по желанию).** Продавец присылает свой токен MPStats → проверка → сохранение в зашифрованном виде. Без MPStats бот работает, но без блока «Рынок и конкуренты».
4. **Себестоимость.** Файл CSV/Excel «артикул; себестоимость» → бот сообщает, сколько строк принято и какие пропущены.
5. **Анализ.** /analyze → прогресс в одном сообщении → итог: топ-5 проблем + полный отчёт PDF.
6. **Мониторинг (v1.1).** Ежедневная короткая сводка и срочные уведомления: «товар закончится через 3 дня», «ДРР кампании вырос до 40 %», «новый негативный отзыв без ответа».
7. **История.** /history — прошлые анализы и их PDF. /shops — выбор и удаление магазинов (до 5).

## 6. Функциональные требования: рынок и конкуренты (MPStats, v2)

### 6.1. Как определяем конкурентов

- По **предмету** (категории) и цене товара продавца: товары того же предмета в ценовом коридоре ±30 %.
- По **ключевым поисковым запросам**: кто стоит рядом в выдаче.
- Продавец может вручную добавить конкурента по артикулу WB.

### 6.2. Проверки рынка

| # | Проверка | Что показывает | Важность |
| --- | --- | --- | --- |
| M1 | Цена относительно рынка | цена выше/ниже медианы конкурентов и как это связано с продажами | важно / совет |
| M2 | Конкурент растёт, вы падаете | у конкурентов продажи растут, у товара продавца падают | критично / важно |
| M3 | Окно возможностей | у сильных конкурентов закончился товар — время усилить рекламу и запасы | важно |
| M4 | Отставание по карточке | рейтинг, число отзывов, фото, описание хуже, чем у лидеров | совет |
| M5 | Позиции в поиске | по ключевым запросам конкуренты выше, позиции падают | важно / совет |
| M6 | Состояние ниши | спрос в нише растёт или падает, насколько она насыщена | совет |

### 6.3. Требования к данным MPStats

- Используется только официальный API MPStats; методы, поля и лимиты берутся из документации MPStats, как и для WB.
- Продажи конкурентов в MPStats — **оценка**. В отчёте такие цифры помечаются «оценка MPStats» и не смешиваются с точными данными WB продавца.
- **Модель доступа (решает заказчик):**
  - **А (рекомендуется):** продавец подключает свой токен MPStats. Каждый пользуется своей подпиской.
  - **Б:** сервис использует один доступ MPStats для всех клиентов. Только при наличии партнёрского договора с MPStats: перепродажа данных без договора обычно запрещена.

## 7. Отчёт

- **Итог** (2–4 предложения): главное и с чего начать.
- **Находки по важности:** критично → важно → совет. Для каждой: что случилось, почему важно, что сделать, цифры, список товаров.
- **Блок «Рынок»** (v2): отдельно, с пометкой об оценочных данных.
- **«Не проверено»:** какие проверки остались без данных и почему (нет доступа в токене, нет себестоимости, сбой WB).
- **Форматы:** короткий итог в Telegram (топ-5) и полный PDF.
- **Текст** пишет Claude по готовым цифрам; при недоступности Claude — шаблонный текст.

## 8. Нефункциональные требования

**Надёжность**
- Сбой одного источника данных не прерывает анализ.
- Соблюдение лимитов WB и MPStats: очередь запросов, повтор при 429 и 5xx, таймауты.
- Анализ выполняется в фоне. Целевое время — до 15 минут: его определяют лимиты WB (часть отчётов — 1 запрос в минуту).

**Безопасность**
- Токены WB и MPStats шифруются (Fernet), ключ хранится только на сервере; ни один токен не попадает в логи.
- Сообщение с токеном удаляется из чата сразу после получения. Токен в группе — удаление и предупреждение.
- Доступ к данным — только владельцу магазина.

**Персональные данные**
- Обрабатываются: Telegram ID, номер телефона, имя.
- Перед началом работы пользователь даёт согласие на обработку персональных данных; публикуется политика конфиденциальности.
- Для пользователей из России персональные данные хранятся на сервере в России (требование 152-ФЗ о локализации). Выбор сервера согласуется с этим.

**Качество кода**
- Python 3.12, типизация, тесты на каждую проверку (включая пустые и ошибочные ответы), ruff и mypy без ошибок.

## 9. Архитектура (кратко)

- **Telegram-бот** — диалог с продавцом.
- **Worker** — фоновые анализы из очереди.
- **Клиенты API:** WB и MPStats — у каждого свой белый список методов, учёт лимитов, повторы.
- **Сборщики данных** переводят ответы API в единый формат.
- **Проверки** — независимые модули с порогами.
- **Отчёт:** Claude плюс проверка чисел, PDF.
- **База MySQL:** пользователи, магазины, зашифрованные токены, себестоимость, история анализов.
- **Развёртывание:** Docker Compose (бот, worker, MySQL) на VPS; резервное копирование базы ежедневно.

## 12. Риски

| Риск | Мера |
| --- | --- |
| WB меняет или отключает методы API | один модуль-адаптер, предупреждения о сбоях данных, отслеживание новостей WB API |
| Лимиты WB делают анализ долгим | фоновый режим, прогресс в чате, кэш данных между анализами |
| Ошибочные выводы по неполным данным | пометки «нет данных» и «возможен сбой», пороги минимальных объёмов |
| Утечка токенов | шифрование, удаление сообщений, только чтение, отзыв токена продавцом |
| Условия MPStats запрещают модель Б | модель А по умолчанию |
| Требования к ПДн | согласие, политика, сервер в РФ для пользователей из России |
