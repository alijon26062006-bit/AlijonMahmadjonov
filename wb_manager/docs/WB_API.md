## Общее

### Авторизация и токены

- Токен передаётся в заголовке **`Authorization`**. Срок действия — **180 дней** с момента создания.
- Токен — **JWT** (RFC 7519). Поля payload:

| Поле | Значение |
|---|---|
| `acc` | тип токена: 1 базовый, 2 тестовый, 3 персональный, 4 сервисный |
| `for` | `self` у персонального, `asid:{ID сервиса}` у сервисного, у остальных нет |
| `t` | `true` только у тестового |
| `id` | UUID токена |
| `s` | битовая маска категорий (см. ниже) |
| `sid` | UUID продавца |
| `exp` | срок действия (RFC 7519) |

- Биты поля `s`: 1 Контент, 2 Аналитика, 3 Цены и скидки, 4 Маркетплейс, 5 Статистика,
  6 Продвижение, 7 Отзывы и вопросы, 9 Чат с покупателями, 10 Поставки, 11 Возвраты покупателями,
  12 Документы, 13 Финансы, 16 Пользователи, **30 — токен только для чтения**.
  - ⚠️ **Сверить:** в коде позиция N трактуется как значение `2**N` (бит 0 — младший). Документация
    это явно не уточняет. Проверим на реальном токене (нужно только число `s`, не сам токен).
    Пока на этой трактовке ничего не блокируется: доступ к категориям подтверждаем ответом `/ping`.

- **Типы токенов и правила WB** (важно для бизнеса):

| Тип | Для чего | Ограничения |
|---|---|---|
| Персональный | собственные программы продавца, в т. ч. на сторонних серверах | **нельзя передавать третьим лицам и использовать в облачных сервисах** |
| Сервисный | облачный сервис из каталога «Решения для бизнеса» WB | работает только с одним сервисом; при нехватке средств у сервиса — ответ 402 |
| Базовый | тестирование на реальных данных и случаи, где другие не подходят | урезанный набор данных, строгие лимиты |
| Тестовый | песочница | только сгенерированные данные |

- Лимиты бывают разными по типу токена: «Персональный», «Сервисный», «Базовый с секретом»
  (зарегистрированный сервис не из каталога передаёт секретный ключ), «Базовый», «Тестовый».
  Как передаётся секретный ключ сервиса — **не описано в присланном тексте**, не реализовано.

### Коды ответов

| Код | Смысл | Что делаем |
|---|---|---|
| 200 / 204 | успех | 204 → пустой результат |
| 400, 409, 413, 422 | ошибка в запросе | ошибка без повтора |
| 401 | токен неверный, просрочен или не передан | ошибка без повтора |
| 402 | у сервиса из каталога нет денег на балансе | ошибка без повтора |
| 403 | нет категории в токене, метод недоступен для типа токена, доступ заблокирован | ошибка без повтора |
| 404 | неверный адрес | ошибка без повтора |
| 429 | слишком много запросов | ждём `X-Ratelimit-Retry` и повторяем |
| 5xx | внутренняя ошибка WB | повтор с растущей паузой |

Форматы тела ошибки:
```json
{"title": "path not found", "detail": "...", "status": 404, "statusText": "Not Found",
 "timestamp": "2025-04-24T07:25:28Z", "requestId": "...", "origin": "..."}
```
```json
{"data": null, "error": true, "errorText": "...", "additionalErrors": "..."}
```

### Лимиты

- Алгоритм WB — token bucket. Лимит метода описан четырьмя числами: период, лимит, интервал, всплеск.
- Лимиты считаются **на аккаунт продавца**.
- Заголовки ответа:
  - `X-Ratelimit-Remaining` — сколько запросов можно отправить без паузы (во всех ответах, кроме 429);
  - `X-Ratelimit-Retry` — через сколько секунд можно повторить после 429;
  - `X-Ratelimit-Limit`, `X-Ratelimit-Reset` — размер всплеска и время его полного восстановления.
- В некоторых категориях (пример — Маркетплейс) **ответ 4xx засчитывается как 10 запросов**.
  Клиент не повторяет 4xx и подстраивается под `X-Ratelimit-Remaining`.

## Контент (токен категории «Контент»)

**Лимит** на аккаунт продавца, общий для всех методов категории:

| Период | Лимит | Интервал | Всплеск |
|---|---|---|---|
| 1 мин | 100 запросов | 600 мс | 5 запросов |

- Свои лимиты у создания, редактирования и восстановления карточек и у рекомендаций (в v1 не используем).
- Песочница: **не более 1 запроса в секунду суммарно** на все методы Контента.

| Метод | Путь | Нужен в v1 |
|---|---|---|
| Родительские категории | `GET /content/v2/object/parent/all` | нет (не включён) |

**Ждут текста документации:** список карточек, карточки с ошибками, характеристики предмета.

## Маркетплейс → Заказы DBW (Delivery by WB)

Токен категории «Маркетплейс». Хост: `marketplace-api.wildberries.ru`.

**Лимит** (общий для методов сборочных заданий, контактов и получения/удаления маркировки):
1 мин / 300 запросов / интервал 200 мс / всплеск 20. **Ответ 4xx считается за 10 запросов.**
У метода отмены указан отдельный лимит для базового токена: 1 ч / 10 запросов / 6 мин / всплеск 1.
Закрепление маркировки: 1 мин / 1000 / 60 мс / 20.

Формат ошибки маркетплейса: `{"code": "IncorrectParameter", "message": ""}`.

| Метод | Путь | Чтение? | Для v1 |
|---|---|---|---|
| Новые сборочные задания | `GET /api/v3/dbw/orders/new` | да | возможно |
| Завершённые сборочные задания | `GET /api/v3/dbw/orders` — `limit` (1–1000), `next` (0 в первом запросе, дальше из ответа), `dateFrom`, `dateTo` (Unix timestamp), период ≤ 30 дней | да | возможно |
| Статусы сборочных заданий | `POST /api/v3/dbw/orders/status` — `{"orders": [id, …]}` до 1000 | да (POST-чтение) | возможно |
| Дата и время доставки | `POST /api/v3/dbw/orders/delivery-date` | да | нет |
| Информация о покупателе | `POST /api/marketplace/v3/dbw/orders/client` | да, **персональные данные** | нет — не забираем |
| Курьер | `POST /api/v3/dbw/orders/courier` | да, персональные данные | нет |
| Стикеры | `POST /api/v3/dbw/orders/stickers` | да | нет |
| Маркировка: получить | `POST /api/marketplace/v3/dbw/orders/meta/details` | да | нет |
| На сборку, отмена | `PATCH …/{orderId}/confirm`, `PATCH …/{orderId}/cancel` | **запись** | запрещено |
| В доставку | `POST /api/marketplace/v3/dbw/orders/status/deliver` | **запись** | запрещено |
| Маркировка: удалить, закрепить | `POST …/meta/delete`, `POST …/meta/sgtin`, `PUT …/meta/uin|imei|gtin` | **запись** | запрещено |

`supplierStatus`: new, confirm, complete, receive, reject, cancel, cancel_missed_call.
`wbStatus`: waiting, sold, canceled, canceled_by_client, declined_by_client, defect,
canceled_by_missed_call, postponed_delivery.

⚠️ **Поля заказа не видны:** в присланном тексте примеры ответов свёрнуты (`"orders": [{}]`).
Пока полей нет, методы в белый список не добавлены.

## Отчёты (раздел «Отчёты» на dev.wildberries.ru, прислан 14.10.2026, на русском)

### Основные отчёты — токен «Статистика», хост `statistics-api` (есть песочница)

**Заказы** `GET /api/v1/supplier/orders` ✅ подключено (сборщик `orders`)
- Параметры: `dateFrom` (RFC3339, **время Москвы UTC+3**; дата или дата-время) — строки с
  `lastChangeDate` > dateFrom; `flag` (0 по умолчанию; 1 — все за день dateFrom).
- 1 строка = 1 заказ = 1 единица товара; уникальный id — `srid`. Хранится 90 дней. Обновление раз в 30 мин.
- До ~80 000 строк за ответ; следующая страница: `dateFrom` = полное `lastChangeDate` последней строки;
  пустой массив `[]` — всё выгружено. Данные предварительные (для мониторинга).
- Лимит: Персональный/Сервисный/Базовый с секретом — 1 мин / 1 / 1 мин / всплеск 10; **Базовый — 3 ч / 1 / 3 ч / 1**.
- Поля (по примеру): date, lastChangeDate, warehouseName, warehouseType («Склад продавца»…),
  countryName, oblastOkrugName, regionName, supplierArticle, nmId, barcode, category, subject, brand,
  techSize, incomeID, isSupply, isRealization, totalPrice, discountPercent, spp, finishedPrice,
  priceWithDisc, isCancel, cancelDate, sticker, gNumber, srid.
- Наши допущения (⚠️ сверить по описанию полей): `date` — время Москвы, как у параметров;
  цена заказа для отчёта — `priceWithDisc` (цена со скидкой продавца).

**Продажи и возвраты** `GET /api/v1/supplier/sales` — ⏸ не подключено
- Параметры и пагинация как у заказов. Лимит: 1 мин / 1 / 1 мин / всплеск **1**; Базовый — 2 ч / 1 / 2 ч / 1.
- Поля (по примеру): … как у заказов + paymentSaleAmount, forPay, saleID («S9993700024»).
- ❓ **Как отличить возврат от продажи — в тексте не сказано** (по saleID? по знаку сумм?). Нужно
  описание полей ответа (раскрыть «200 Успешно» → схема).

### Аналитика — токен «Аналитика», хост `seller-analytics-api` (песочницы нет)

**Остатки на складах WB** (асинхронный отчёт) — ⏸ не подключено
- `GET /api/v1/warehouse_remains` (создать; groupByNm и др.) → `GET …/tasks/{task_id}/status` →
  `GET …/tasks/{task_id}/download`. Готовый отчёт хранится 2 ч.
- Лимиты: создать 1 мин/1/1 мин/5 (Базовый 1 ч/4/15 мин/1); статус 5 с/1/5 с/5; скачать 1 мин/1/1 мин/1.
- ❓ Поля внутри `warehouses: []` не видны — нужен раскрытый пример.

**Платное хранение** (асинхронный отчёт) ✅ подключено (сборщик `paid_storage`)
- `GET /api/v1/paid_storage?dateFrom&dateTo` — **максимум 8 дней** за отчёт → статус → скачать (204 — нет данных).
- Лимиты: создать 1 мин/1/1 мин/5 (Базовый 1 ч/1/1 ч/1); статус 5 с/1/5 с/5 (Базовый 1 ч/2/30 мин/2);
  скачать 1 мин/1/1 мин/1 (Базовый 1 ч/2/30 мин/1).
- Статус готовности: `"done"` (другие значения в тексте не перечислены — ждём done, иначе таймаут).
- Поля: date, logWarehouseCoef, officeId, warehouse, warehouseCoef, giId, chrtId, size, barcode,
  subject, brand, vendorCode, nmId, volume, calcType, warehousePrice, barcodesCount, palletPlaceCode,
  palletCount, originalDate, loyaltyDiscount, tariffFixDate, tariffLowerDate.
- Допущение (⚠️ сверить): `warehousePrice` — стоимость хранения строки за день `date`, ₽.

**Операции при приёмке** (асинхронный, максимум 31 день) — поля: count, giCreateDate, incomeId, nmID,
shkCreateDate, subjectName, total. Это платная приёмка, а не расхождения «отгружено/принято» — пока не используем.

**Отчёты об удержаниях** — пути и лимиты известны, поля свёрнуты (не подключено):
`GET /api/analytics/v1/measurement-penalties` (занижение габаритов), `…/warehouse-measurements`,
`…/deductions` (подмены и неверные вложения), `GET /api/v1/analytics/antifraud-details` (самовыкупы,
еженедельно по средам), `GET /api/v1/analytics/goods-labeling` (маркировка, ≤31 дня).

**Заблокированные карточки** `GET /api/v1/analytics/banned-products/blocked?sort&order` — поля свёрнуты.
**Возвраты** `GET /api/analytics/v1/item-returns` (новый; `goods-return` отключат 26 октября) — поля свёрнуты.
**Продажи по регионам** — отключат 3 ноября. **Доля бренда**, **маркировка (excise-report)** — для v1 не нужны.
