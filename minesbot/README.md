# 💣 Mines — телеграм-бот с игрой на виртуальные монеты

Поле 5×5, под клетками спрятаны мины. Каждая открытая пустая клетка поднимает
множитель. Нажал **💰 Гирифтан** до мины — забрал выигрыш. Попал в мину — ставка
сгорела. Монеты **виртуальные**: их нельзя купить и нельзя вывести.

---

## Установка одной командой

На сервере (Ubuntu / Debian / любой Linux) выполни:

```bash
curl -fsSL https://raw.githubusercontent.com/alijon26062006-bit/AlijonMahmadjonov/claude/telegram-bot-game-24dkzl/minesbot/install.sh | bash
```

Дальше установщик всё делает сам и **спросит только токен**:

```
[1/5] Система          — проверит python3, доставит git/curl/venv
[2/5] Код бота         — скачает репозиторий в ~/mines-bot
[3/5] Зависимости      — создаст .venv-mines и поставит библиотеки
[4/5] Токен бота       — спросит токен, проверит его у Telegram (getMe)
[5/5] Запуск           — сделает systemd-сервис и запустит бота
```

Где взять токен: Телеграм → **@BotFather** → `/newbot` → скопировать строку
вида `123456789:AAE_hs1k…`. Установщик её проверяет: если токен неверный —
скажет об этом сразу и спросит заново, а не оставит мёртвого бота.

После установки открой своего бота и напиши `/start`.

### Повторный запуск = обновление

Та же самая команда обновляет уже установленного бота: код подтянется из git,
токен возьмётся из сохранённого `.env.mines`, сервис перезапустится.

### Управление

| Что | Команда |
|---|---|
| Логи вживую | `sudo journalctl -u minesbot -f` |
| Остановить | `sudo systemctl stop minesbot` |
| Запустить | `sudo systemctl start minesbot` |
| Статус | `systemctl status minesbot` |
| Обновить | `bash ~/mines-bot/minesbot/install.sh` |
| Бэкап данных | `cp ~/mines-bot/data/mines.db ~/mines-backup.db` |

Бот стоит на `Restart=always`: упал — systemd поднимет его через 5 секунд,
сервер перезагрузился — бот стартует сам.

| Команда | Что делает |
|---|---|
| `/start`, `/help` | правила и список команд |
| `/bet 100` | начать игру со ставкой 100 (можно просто написать `100`) |
| `/mines 5` | сколько мин класть в следующих играх (1–24) |

| `/stats` | сколько сыграно, выиграно, проиграно |

## Как считается выигрыш

Множитель не выдуман — он честный, обратный вероятности:

```
M(k) = (1 − edge) × Π (25 − i) / (25 − мин − i),   i = 0 … k−1
```

Открыть подряд `k` пустых клеток тем труднее, чем больше мин, — ровно во
столько же раз растёт выплата. `edge` (по умолчанию `0.03`) — комиссия
заведения: без неё игра была бы в ноль и казна пустела бы от дисперсии.
Округление всегда **вниз**, в пользу казны: иначе на больших ставках копейки
утекают наружу.

При 3 минах: `x1.10 · x1.25 · x1.44 · x1.67 · x1.95 · x2.30 …`
При 24 минах одна безопасная клетка даёт сразу `x24.25`.

Расклад мин берётся из `secrets` (криптографический источник), а не из
`random`: по прошлым играм следующую предсказать нельзя.

## Аудит старого кода: что было сломано и как починено

Ниже — построчный разбор присланного варианта. Каждый пункт: **что было** →
**чем это грозит** → **как сделано теперь**.

### 🔴 Критичные (деньги и доступ)

**1. `main()` вызывается прямо в конце файла**
Было: последняя строка файла — `main()`. Любой импорт модуля (тест, линтер,
второй процесс) немедленно начинал опрашивать Telegram. Два процесса на одном
токене → Telegram отдаёт `Conflict: terminated by other getUpdates`, и бот
молча перестаёт отвечать.
Стало: запуск только через `python -m minesbot`, точка входа под
`if __name__ == "__main__"` → `minesbot/main.py`.

**2. Токен лежал в коде**
Было: `TOKEN = "…"` в исходнике, который уходит в git. Токен в репозитории =
чужой человек забирает бота себе (читает все сообщения, пишет от его имени).
Стало: токен только в `.env.mines` с правами `600`, файл в `.gitignore`,
формат проверяется при старте, а установщик ещё и спрашивает у Telegram
`getMe` — токен с опечаткой не доедет до продакшена.
👉 **Если твой старый токен хоть раз был в коде или в переписке — отзови его:
@BotFather → `/revoke`.**

**3. Всё состояние — в памяти (`games = {}`, баланс в словаре)**
Было: перезапуск/падение/деплой — и балансы всех игроков, и незаконченные
партии исчезают. Игрок, у которого ставка была списана, остаётся ни с чем.
Стало: SQLite (`data/mines.db`) в режиме WAL. Незаконченная партия переживает
перезапуск, кнопки продолжают работать (`minesbot/db.py`).

**4. Перевод монет — две отдельные операции**
Было:
```python
add_money(uid, -amount)
add_money(receiver.id, amount)
```
Между этими строками процесс может умереть (или быть убит OOM-killer'ом) —
монеты списаны и никому не пришли. Плюс проверка `balance(uid) < amount` и само
списание разнесены во времени: два быстрых `/send` подряд списывают дважды с
одного баланса (классический TOCTOU-двойной расход).
Стало: `db.transfer()` — одна транзакция `BEGIN IMMEDIATE`, проверка и оба
изменения внутри неё, плюс `CHECK (balance >= 0)` на уровне таблицы.

**5. Двойное нажатие «Забрать» = двойная выплата**
Было: `if uid not in games` → `add_money(uid, win)` → `del games[uid]`. При
параллельной обработке два нажатия успевают пройти проверку до удаления.
Стало: `db.finish_game()` закрывает игру условием `WHERE status = 'active'` в
транзакции. Второе нажатие получает `NoGame` и ответ «Бозӣ тамом шудааст»,
деньги не начисляются второй раз. Это покрыто тестом `test_cashout_pays_once`.

**6. Ставка не списывалась в начале игры**
Было: выигрыш начислялся, а списания ставки в коде нет. Игра без риска —
баланс мог только расти.
Стало: `db.start_game()` списывает ставку той же транзакцией, в которой
создаёт партию. Проиграл — деньги уже ушли, дополнительных операций не нужно.

**7. Одна и та же клетка засчитывалась дважды**
Было: `if index in game["opened"]: return` и следом `append` — между ними
может вклиниться второе нажатие, и множитель вырастет за одно открытие дважды.
Стало: (а) у открытой клетки callback-кнопка заменяется на «пустышку»
`mn:x:0:0`, (б) запись открытия идёт транзакцией, (в) на игрока висит
`asyncio.Lock`. Тест: `test_same_cell_twice_counts_once`.

**8. Кнопки старого сообщения управляли новой игрой**
Было: игра ищется по `games[uid]`, а в `callback_data` игры нет. Открыл старое
сообщение, нажал клетку — ход применился к текущей партии.
Стало: `callback_data = mn:<действие>:<game_id>:<клетка>`, `game_id` сверяется
с активной партией. Старая кнопка отвечает «Бозӣ тамом шудааст» и снимает с
мёртвого сообщения клавиатуру. Тест: `test_stale_button_from_old_message`.

### 🟠 Логика игры

**9. Множитель складывался, а не умножался**
Было:
```python
multiplier = int(value.replace("x", ""))
win = game["bet"] * multiplier
game["win"] += win          # ← сложение
```
Выплата переставала быть связана с риском: открыл 10 клеток по «x2» — получил
20 ставок за игру, где честная цена ≈ 3. Казна уходит в минус на дистанции.
Плюс множитель разбирался из текста кнопки (`"x3"` → `3`): любая правка
оформления ломала математику.
Стало: множитель считается формулой от числа открытых клеток и числа мин
(`minesbot/game.py`), в тексте кнопки он только отображается.

**10. Число мин и номиналы клеток были зашиты в раскладку**
Стало: мины раскладываются `secrets`, их количество настраивается `/mines N` и
переменной `MINES_COUNT`, математика пересчитывается автоматически.

**11. Не было выигрыша «поле пройдено целиком»**
Было: если открыть все безопасные клетки, игра просто зависала — жать больше
некуда, а выплаты нет.
Стало: `is_cleared()` → бот сам выплачивает и закрывает партию 🏆.

**12. Можно было начать вторую игру поверх первой**
Было: `games[uid] = …` перезаписывал партию, старая ставка сгорала молча.
Стало: уникальный индекс в базе `games_one_active` — вторую активную партию
не даст создать сама СУБД, бот отвечает «Ту аллакай бозӣ дорӣ».

**13. `games` рос вечно**
Брошенные партии никогда не удалялись — медленная утечка памяти.
Стало: состояние в базе, в памяти не копится ничего.

### 🟡 Устойчивость и ошибки

**14. Команды не работали вообще**
Было: единственный обработчик — `MessageHandler(filters.TEXT & ~filters.COMMAND)`.
То есть `/start`, `/help`, `/balance` фильтром **отсекались**, а `CommandHandler`
не добавлен ни один. Новый человек писал `/start` и не получал ничего.
Стало: `CommandHandler` на каждую команду + меню команд в интерфейсе Телеграма
(`set_my_commands`).

**15. `q.data.split(":")` без проверок**
Было: `action = data[0]; uid = int(data[1]); index = int(data[2])`. Любой
неожиданный `callback_data` (старый формат, чужая кнопка, обрезка) →
`IndexError`/`ValueError` → необработанное исключение на каждое нажатие.
Стало: строгий разбор — ровно 4 части, иначе тихий `answer()`. Тест:
`test_broken_callback_data_is_ignored`.

**16. Нажатие без ответа — «часики» навсегда**
Было: на ветке «клетка уже открыта» стоял голый `return` без `q.answer()`.
Telegram крутит спиннер на кнопке ~30 секунд, человек думает, что бот завис.
Стало: каждая ветка обработчика заканчивается `answer()`.

**17. Не было обработчика ошибок**
Стало: `add_error_handler` — ошибка пишется в лог с трассировкой, а человеку
приходит «⚠️ Хатогӣ шуд», а не тишина.

**18. После простоя бот отыгрывал старые нажатия**
Стало: `run_polling(drop_pending_updates=True)` — вчерашние нажатия не
исполняются на сегодняшнем балансе.

**19. Не было защиты от flood-limit**
Телеграм режет бота, который пишет слишком часто; без очереди сообщения просто
терялись. Стало: `AIORateLimiter` (очередь и повторы).

**20. Чужое имя подставлялось в сообщение как есть**
Ник вида `<b>` ломал разметку сообщения (а при `parse_mode=HTML` — это готовая
инъекция в текст бота). Стало: `html.escape()` для любого имени.

**21. Бот жил, пока открыт SSH**
Стало: systemd-сервис, автозапуск после перезагрузки, `Restart=always`,
`NoNewPrivileges`, `PrivateTmp`.

**22. Тестов не было ни одного**
Стало: **49 тестов** — математика, транзакции базы и сквозные сценарии с
поддельным Телеграмом (двойные нажатия, чужие кнопки, перевод, взрыв, бонус).

### ⚪️ Мелочи, которые всё равно важны

- `"🚀"` как мина — из другой игры (Crash); теперь 💣, а открытая клетка — 💎.
- Не было ограничения на ставку — теперь `MIN_BET` / `MAX_BET`.
- Не было `/send` самому себе — проверка добавлена.
- Получатель перевода мог быть не зарегистрирован — теперь заводится до перевода.
- Не было ни логов, ни уровня логирования — теперь `LOG_LEVEL`.
- Не было истории операций — теперь таблица `ledger`: по ней видно
  происхождение каждой монеты, и баланс пересобирается суммой `delta`.
