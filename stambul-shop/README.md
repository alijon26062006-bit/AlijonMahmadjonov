# Stambul Shop — магазин одежды, обуви и товаров для дома

Обычный сайт: человек открывает ссылку в браузере и покупает. Telegram при
нём служебный — присылает код подтверждения при входе и сообщения о
заказах. Доставка по Казахстану, оплата переводом на Kaspi.

## Что внутри

| Часть | Стек | Папка |
|---|---|---|
| Сайт и панель | React 18, Vite, TypeScript | `web/` |
| API | FastAPI, SQLAlchemy 2 async | `backend/app/api` |
| Разделы и поля | декларативные схемы | `backend/app/catalog` |
| Бот: коды и уведомления | Python 3.12, aiogram 3 | `backend/app/bot` |
| Письма и уведомления | arq, SMTP | `backend/app/workers` |
| БД | PostgreSQL 16, Redis 7 | docker-compose |

## Главное решение: товар ≠ вариант

Одна футболка — это **карточка** плюс набор **вариантов** «размер + цвет».
Остаток и цена живут в варианте, покупатель кладёт в корзину именно его.
Отсюда всё остальное:

- кончился размер — он гаснет в карточке зачёркнутым, товар остаётся;
- кончились все — карточка уходит из «в наличии» сама, при завозе возвращается;
- цена карточки — минимальная среди доступных вариантов, пересчитывается сама;
- скрытый вручную товар остаётся скрытым: это решение человека, а не склада.

Состояния карточки: `draft` (нет фото или размеров) → `active` → `out`
(закончился) и `hidden` (снят вручную).

## Вход без паролей

Паролей в магазине нет — ни заводить, ни восстанавливать, ни хранить.
Есть два способа войти, и оба подтверждает не наш сервер.

**По номеру телефона.** Человек вводит номер, сайт даёт ссылку на бота и
QR-код рядом — с компьютера удобнее навести камеру, чем набирать адрес.
В боте одна кнопка, «Отправить мой номер»: номер в неё подставляет сам
Telegram, руками туда ничего не впишешь. Совпал с введённым на сайте — бот
присылает шесть цифр. Вкладка всё это время ждёт и может впустить сразу
после подтверждения; код нужен, если вернулись с другого устройства.

Без сверки контакта любой мог бы ввести чужой номер и получить код себе —
поэтому шаг с кнопкой не украшение.

**Через Google.** Почту Google подтвердил до нас, подтверждать нечего.
Телефон у такого покупателя спросим при первом заказе: доставка без него
невозможна.

Один человек — один аккаунт: совпал телефон, почта или Telegram-id, это
тот же человек, недостающее дописывается в профиль. Занятое чужим
аккаунтом не отбирается — сливать два живых аккаунта с их заказами должен
человек, а не программа.

## Разделы

```
Одежда:              женская · мужская · нижнее бельё
Обувь и аксессуары:  обувь · сумки и аксессуары
Детям:               детская одежда · игрушки
Для дома:            текстиль · посуда и кухня · бытовая техника
```

У каждого раздела свои поля и своя размерная линейка: у обуви 35–46, у
детского возраст и рост, у белья бюстгальтерные размеры, у посуды один
размер. Новый раздел — одна запись в `backend/app/catalog/schemas.py`;
ни база, ни интерфейс не меняются.

## Как идёт заказ

1. Покупатель выбирает размер и цвет, кладёт в корзину. Корзина живёт в базе:
   положил с телефона — видно с компьютера. Остаток при этом **не
   резервируется**: пока заказ не оформлен, вещь может купить другой.
2. Оформление: имя, телефон, город, адрес, способ доставки. Адрес прошлого
   заказа подставляется сам.
3. Списание склада — единственное место с блокировкой строк (`SELECT … FOR
   UPDATE`). Два человека не купят одну последнюю вещь: второй получит
   «Осталось только 0 шт.», а не молчаливый минус.
4. Заказ падает владельцу в бот карточкой с кнопками, покупателю — письмо
   и сообщение с реквизитами Kaspi.
5. Статусы идут строго по цепочке: `Новый → Подтверждён → Оплачен →
   Отправлен → Получен`, отмена возможна на любом шаге до получения.
   **Отмена возвращает вещи на склад.**

Письмо о принятом заказе уходит независимо от переключателей уведомлений:
в нём реквизиты, без которых человек просто не сможет заплатить.

## Каталог открыт по умолчанию

Закрытый регистрацией каталог не индексируется поисковиками, и присланная
другу ссылка открывается у него стеной входа — для сайта это дорого. Поэтому
смотреть можно без входа, а он требуется в корзине и при оформлении.
Закрывается одной настройкой `REQUIRE_AUTH_TO_BROWSE=1`, без правки кода.

Роботам сервер отдаёт то, чего одностраничное приложение дать не может:
`sitemap.xml` со всеми товарами, `robots.txt` и разметку страницы товара с
заголовком, ценой и картинкой — по ней мессенджер рисует превью ссылки.
Человека на эти ответы nginx не пускает.

## Доставка и оплата

Курьером по городу, почтой по Казахстану, самовывоз (если задан
`PICKUP_ADDRESS`). Бесплатно от суммы `FREE_DELIVERY_FROM`. Города со сроками
доставки — в справочнике, правятся в панели.

Оплата — переводом на Kaspi: `KASPI_PHONE` и `KASPI_NAME` показываются
покупателю после оформления, номер заказа он указывает в комментарии к
переводу. Встроенный приём карт требует юрлица и договора с банком — на
старте не нужен.

## Быстрый старт

На чистом сервере — один скрипт. Понимает и Debian/Ubuntu (`apt`), и
RHEL-семейство: AlmaLinux, Rocky, CentOS (`dnf`). Ставит Docker, спрашивает
токен бота, ваш id и домен, подбирает свободные порты, собирает магазин,
настраивает nginx и выпускает сертификат:

```bash
sudo bash install.sh
```

Повторный запуск безопасен: уже сделанное пропускается, введённые значения
предлагаются как есть. Перед выпуском сертификата скрипт сверяет A-запись
домена с адресом сервера и честно скажет, если они расходятся.

Попутно снимаются грабли, на которых обычно теряют вечер: на машине меньше
2 ГБ добавляется файл подкачки (иначе сборка витрины падает без объяснений),
в firewalld или ufw открываются порты 80 и 443, а на RHEL снимается запрет
SELinux на исходящие соединения nginx — без него магазин отвечает 502 на
пустом месте.

Вручную, если предпочитаете контроль:

```bash
cp .env.example .env      # заполнить BOT_TOKEN, ADMIN_IDS, SITE_URL
docker compose build
docker compose run --rm migrate
docker compose up -d
```

Обновление на работающем сервере:

```bash
git pull
docker compose build          # собирает и migrate: у него профиль tools,
docker compose run --rm migrate   # и «up --build» его не трогает
docker compose up -d --remove-orphans
```

Проверка: `curl localhost:8010/health` → `{"db":"ok"}`; открыть сайт в браузере.

### Что задать в `.env`

1. **BOT_TOKEN** и **BOT_USERNAME** — от @BotFather.
2. **ADMIN_IDS** — свой Telegram-id, узнать командой `/id` у бота. Это
   единственный источник правды о правах: список сверяется при каждом
   действии, правка `.env` требует перезапуска контейнеров.
3. **SITE_URL** — адрес магазина, с него собираются ссылки в письмах и
   карте сайта.
4. **STORAGE_CHAT_ID** — приватная группа-хранилище фотографий, бота туда
   админом. Без неё фотографии товаров загружать некуда.
5. **GOOGLE_CLIENT_ID** — если нужен вход через Google. Берётся в
   console.cloud.google.com → Credentials → OAuth client ID → Web
   application, адрес сайта вписывается в «Authorized JavaScript origins».
6. **SMTP_HOST**, **SMTP_USER**, **SMTP_PASS**, **MAIL_FROM** — письма о
   заказах. Без них работают только сообщения в Telegram.
7. **KASPI_PHONE**, **KASPI_NAME** — реквизиты, которые увидит покупатель.

**Один токен — один бот.** Если тот же `BOT_TOKEN` уже используется другим
проектом, его нужно остановить: Telegram отдаёт двум одновременным polling
ошибку 409, и молчат оба.

## Управление магазином

Панель — `/admin` на сайте, у владельца ссылка появляется в профиле.

- **Заказы** — карточка с составом, телефоном и адресом; статус меняется
  кнопкой, для отправки вводится трек-номер.
- **Товары** — поиск, таблица «размер · цвет · цена · остаток», загрузка
  фотографий, скрыть, удалить.
- **Добавить товар** — раздел, название, бренд, описание и поля раздела.
  После создания задаются размеры и фотографии.

В боте: `/panel` — сводка (товары, склад, заказы, выручка, что заканчивается),
`/orders` — заказы покупателя, `/id` — свой Telegram-id и права.

## Разработка без Docker

```bash
cd backend
pip install -r requirements.txt
python -m app.db.create
uvicorn app.api.main:app --reload --port 8020
python -m app.bot
arq app.workers.worker.WorkerSettings

cd ../web
npm install && npm run dev
```

## Проверено

Интеграционно, на настоящих PostgreSQL и Redis — 85 проверок.

Вход (31): нормализация номера во всех привычных написаниях, чужой номер в
боте, одноразовость кода и лимит попыток, вход без ввода цифр после
подтверждения, ограничение частоты запросов, слияние аккаунтов и защита
занятого Telegram.

Магазин (54): заведение товара и отбраковка чужих полей, повторы вариантов
и нулевые цены, оживление карточки из черновика, витрина и фильтры по полям
раздела, корзина с потолком по остатку, оформление с проверкой полей, гонка
двух покупателей за последней вещью, уход товара с витрины при нуле, цепочка
статусов и возврат склада при отмене, права и сводка.

Запуск — `backend/tests/README.md`.
