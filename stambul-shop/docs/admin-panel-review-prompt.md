# Панель управления магазином: что есть сейчас и что с этим делать

Документ для стороннего разбора. Ниже — честное описание того, как панель
устроена сегодня, без прикрас. Вопрос в конце.

---

## 1. Что за магазин

**Stambul Shop** — интернет-магазин одежды, обуви, аксессуаров, детских
вещей, посуды и бытовой техники. Доставка по Казахстану, оплата переводом
на Kaspi.

Это обычный сайт, а не приложение внутри мессенджера. Telegram участвует
только в двух местах: присылает код при входе по номеру телефона и шлёт
сообщения о заказах тем, кто привязал бота.

**Магазин одного владельца.** Товары добавляет один человек — хозяин.
Никаких других продавцов, поставщиков, менеджеров и складских работников
нет и не планируется. Покупатели только покупают.

Стек: React 18 + TypeScript + Vite на витрине, FastAPI + SQLAlchemy 2
(async) + PostgreSQL 16 + Redis на сервере, aiogram 3 для бота, arq для
фоновых задач, всё в Docker Compose за nginx.

Модель данных, важная для понимания: **товар ≠ вариант**. Карточка товара
хранит название, описание, бренд, раздел и произвольные поля раздела.
Цена и остаток живут в вариантах «размер + цвет». Цена карточки —
минимальная среди доступных вариантов, пересчитывается автоматически.
Состояние карточки тоже производное: нет фото или вариантов — `draft`,
все остатки нулевые — `out`, иначе `active`; отдельно есть `hidden` для
снятого вручную.

Дизайн строго монохромный: белый фон, чёрный текст, тёмно-серые оттенки.
Цвет в интерфейсе появляется только от фотографий товара. Красный — только
для ошибок.

## 2. Кто и как пользуется панелью

Один человек, владелец. Права определяются списком Telegram-id в
переменной `ADMIN_IDS` и сверяются при каждом запросе — отдельной роли в
базе нет, есть флаг `is_admin`, который синхронизируется с этим списком
при каждом входе.

Работает он в основном **с телефона**. Компьютер бывает не всегда.

Панель — это раздел того же сайта по адресу `/admin`, а не отдельное
приложение. Ссылка на неё появляется в профиле только у владельца.

Дополнительно в боте есть команда `/panel` — она присылает текстовую
сводку: сколько товаров, сколько на складе, заказы по состояниям,
выручка за неделю и за всё время, средний чек, что заканчивается.

## 3. Что панель умеет сегодня

Один экран, три вкладки-чипа: **Заказы**, **Товары**, **Добавить товар**.
Сверху — четыре плитки со счётчиками и блок «Заканчивается».

### 3.1 Шапка панели

Четыре числа: новые заказы, заказы в работе, активных товаров, единиц на
складе. Под ними — список до пяти вариантов с остатком 1–2 штуки.

### 3.2 Вкладка «Заказы»

Список последних заказов (до 50). Каждый — карточка: номер, состояние,
сумма, состав (название · размер · цвет × количество), имя и телефон
покупателя, способ доставки, город, адрес, комментарий.

Под карточкой — кнопки перехода в следующие состояния. Цепочка жёсткая:
`Новый → Подтверждён → Оплачен → Отправлен → Получен`, отмена возможна на
любом шаге до получения. Через голову перескочить нельзя. Отмена
возвращает вещи на склад. Для перехода в «Отправлен» рядом появляется
поле ввода трек-номера.

Фильтра по состоянию, поиска по номеру или телефону, постраничной
навигации — нет.

### 3.3 Вкладка «Товары»

Строка поиска по названию и бренду, список до 60 карточек. В карточке:
миниатюра, название, бренд, цена, состояние, число фотографий, суммарный
остаток, число продаж.

Внутри карточки два редактора:

- **Варианты** — таблица «размер · цвет · цена · остаток · артикул».
  Строки добавляются и удаляются, сохраняется набор целиком одной кнопкой.
  Повтор пары «размер + цвет» отвергается, нулевая или отрицательная цена
  отвергается.
- **Фотографии** — загрузка файлов. Файл уходит на сервер, тот пересылает
  его в приватную группу Telegram и хранит у себя только идентификатор.
  Порядок фотографий = порядок загрузки, поменять его нельзя.

Ещё есть «скрыть/показать» и «удалить».

Фильтров по разделу и состоянию в интерфейсе нет, хотя API их принимает.
Массовых действий нет. Сортировка одна — по времени изменения.

### 3.4 Вкладка «Добавить товар»

Форма: раздел, название, бренд, описание, старая цена, поля выбранного
раздела (они разные — у обуви одни, у посуды другие). После сохранения
товар создаётся в состоянии `draft`, и панель переключается на список,
где ему нужно задать варианты и фотографии.

То есть завести товар целиком за один проход нельзя: сначала карточка,
потом отдельно размеры, потом отдельно фотографии.

### 3.5 Что есть в API, но не выведено в интерфейс

- `GET /api/admin/log` — журнал действий владельца (кто, что, когда).
- `POST /api/admin/cities` — добавить город со сроком доставки.
- `POST /api/admin/brands` — добавить бренд.
- фильтры `status` и `category` в списке товаров.
- в сводке возвращается выручка за неделю и за всё время, средний чек,
  разбивка заказов по состояниям — на экране из этого нет ничего.

### 3.6 Полный список endpoint'ов панели

```
GET    /api/admin/summary                      сводка
GET    /api/admin/products?q=&status=&category= список товаров
POST   /api/admin/products                     создать
PATCH  /api/admin/products/{id}                изменить карточку
PUT    /api/admin/products/{id}/variants       заменить набор вариантов
PUT    /api/admin/products/{id}/photos         заменить набор фотографий
POST   /api/admin/products/{id}/visibility     скрыть / показать
DELETE /api/admin/products/{id}                удалить
GET    /api/admin/orders?status=&limit=        список заказов
POST   /api/admin/orders/{id}/status           сменить состояние
POST   /api/admin/cities                       добавить город
POST   /api/admin/brands                       добавить бренд
GET    /api/admin/log                          журнал действий
```

## 4. Что смущает меня самого

Перечисляю честно, чтобы разбор не тратился на очевидное:

1. **Заведение товара разорвано на три шага.** Карточка, потом варианты,
   потом фотографии — и всё в разных местах интерфейса. Заводить пятьдесят
   позиций так невозможно.
2. **Нет массовых действий.** Поднять цену на раздел, добавить остаток
   после завоза, скрыть десяток позиций — только по одной.
3. **Нет загрузки списком.** Товары приходят партией, а вводятся руками.
4. **Заказы без фильтра и поиска.** Когда их станет двести, найти нужный
   будет нечем.
5. **Деньги посчитаны, но не показаны.** Выручка и средний чек есть в
   ответе сервера и в боте, а на экране панели их нет.
6. **Журнал действий не выведен.** Владелец один, но история изменений
   всё равно полезна — понять, когда и почему пропал остаток.
7. **Справочники правятся только через API.** Города и бренды добавить
   из интерфейса нельзя.
8. **Панель под телефон не продумана.** Таблица вариантов на узком экране
   тесная, загрузка фотографий с телефона не проверялась всерьёз.
9. **Нет черновиков и предпросмотра.** Владелец не видит карточку глазами
   покупателя перед публикацией.
10. **Нет обратной связи после действия.** Сохранил — и непонятно,
    сохранилось ли; сообщений и подтверждений почти нет.

## 5. Что нужно от разбора

Опиши, как должна выглядеть **одна правильная панель управления** для
такого магазина. Не список фич вообще, а то, что действительно нужно
владельцу-одиночке, который работает с телефона и заводит товары партиями.

Хочу получить:

1. **Структуру панели** — какие разделы, в каком порядке, что на главном
   экране. Обоснуй, почему именно так, а не иначе.
2. **Сценарий «завести товар»** — как он должен выглядеть от начала до
   конца, чтобы двадцать позиций заводились без страданий. Считаю это
   главной болью.
3. **Сценарий «пришёл завоз»** — как быстро обновить остатки по многим
   товарам сразу.
4. **Экран заказов** — что показывать, как искать, как не потерять
   срочное среди старого.
5. **Какие числа выводить на главный экран панели** и почему именно эти.
   Что из них помогает принимать решения, а что просто красиво.
6. **Что из моего списка «что смущает» некритично** и его можно спокойно
   отложить, а что нужно делать в первую очередь. Расставь по порядку.
7. **Чего в моём списке не хватает** — что я упустил и пойму слишком
   поздно.

Ограничения, которые нельзя нарушать:

- владелец один, ролей и разграничения прав не нужно;
- панель живёт внутри того же сайта, отдельного приложения не будет;
- интерфейс монохромный: белый, чёрный, тёмно-серый, красный только для
  ошибок;
- основное устройство — телефон;
- товар и вариант остаются разными сущностями, остаток живёт в варианте;
- фотографии хранятся в Telegram, у нас только идентификаторы;
- язык интерфейса русский.

Если считаешь, что какое-то из ограничений мешает делу — скажи прямо и
объясни, чем именно, но решение предложи в двух вариантах: с ограничением
и без него.
