# Stambul Shop — промт на полное обновление

Документ описывает, каким магазин должен стать. Его можно отдать
разработчику или ИИ целиком: всё, что нужно для работы, здесь.

---

## 0. Рамка: что это и чего нельзя

**Stambul Shop** — обычный сайт. Человек открывает ссылку в браузере и
смотрит товары. Никакого Telegram Mini App: приложения внутри мессенджера
не будет, `initData`, кнопка меню у бота, `WebAppInfo` и хаптика из кода
удаляются.

Telegram остаётся ровно для одного: **бот присылает код подтверждения при
регистрации** и, кто захочет, уведомления о заказах. Больше ничего.

Позиционирование: магазин одежды, обуви, аксессуаров и товаров для дома с
доставкой по Казахстану.

**Запрет.** Слова «Турция», «турецкий», «из Турции» не встречаются нигде:
интерфейс, описания разделов, тексты бота, письма, README, og-теги.
Проверка — поиск по всему коду не даёт ни одного совпадения.

Что переписать первым делом:
- `SHOP_TAGLINE` в `.env` и `.env.example`
- первая строка `README.md`
- приветствие бота в `backend/app/bot/handlers/start.py`
- `<title>` и `<meta name="description">` в `index.html`

Новая подпись: **«Одежда, обувь и всё для дома. Доставка по Казахстану»**.

## 1. Главная для нового посетителя

Человек пришёл по ссылке и не знает, куда попал. Первое, что он видит, —
не каталог, а короткий рассказ о магазине: три блока, по одной мысли в
каждом.

На телефоне это три экрана с листанием пальцем и точками-индикаторами.
На компьютере — те же три блока подряд на одной странице, листаются
прокруткой. Разметка одна, различается только раскладка.

| # | Заголовок | Текст |
|---|---|---|
| 1 | Всё для себя и для дома | Одежда, обувь, аксессуары, детские вещи, посуда и техника — в одном месте |
| 2 | Размер и цвет — честно | Показываем только то, что действительно есть на складе. Кончился размер — вы увидите это сразу |
| 3 | Доставка по Казахстану | Курьером, почтой или самовывозом. Оплата через Kaspi после подтверждения заказа |

Под ними две кнопки: «Смотреть каталог» и «Войти». Сверху справа —
«Пропустить». Один раз просмотренное знакомство больше не показывается:
до входа флаг лежит в `localStorage`, после — в поле `onboarding_done`.

## 2. Регистрация

Экран входа: логотип, строка «Войдите, чтобы оформлять заказы и следить
за доставкой», два способа.

### 2.1 Номер телефона, код из Telegram

Основной способ. Порядок:

1. Поле с маской `+7 (___) ___-__-__`, кнопка «Получить код».
2. Сайт создаёт заявку и показывает кнопку **«Получить код в Telegram»** —
   это ссылка `t.me/<бот>?start=c_<ключ>`. Рядом QR-код: если человек
   сидит с компьютера, он наводит телефон и попадает в бота.
3. В боте одна кнопка — «Отправить мой номер» (стандартная кнопка
   Telegram `request_contact`). Бот сверяет присланный номер с тем, что
   ввели на сайте. Не совпал — так и пишет, кода не даёт.
4. Совпал — бот присылает шесть цифр.
5. Человек возвращается на сайт и вводит их: шесть отдельных клеток,
   автофокус, вставка из буфера заполняет все сразу.
6. Повторная отправка — через 60 секунд, таймер виден. Пять неверных
   попыток — код сгорает, начинаем заново. Жизнь кода — 5 минут.

Вкладка на сайте всё это время ждёт: как только бот подтвердил номер,
она может впустить человека сама, не дожидаясь ввода цифр. Код при этом
остаётся — на случай, если вкладку закрыли или вошли с другого устройства.

Сверка номера через `request_contact` — не украшение. Без неё любой мог
бы ввести чужой номер и получить код себе; с ней Telegram сам ручается,
что номер принадлежит тому, кто его отправляет.

### 2.2 Google

Вторая кнопка — белая, с рамкой и логотипом G. OAuth 2.0, проверка
`id_token` по ключам Google на бэкенде, `GOOGLE_CLIENT_ID` в `.env`.
Берём `sub`, `email`, `name`, `picture`. Ни кода, ни подтверждения —
Google уже подтвердил почту за нас.

Телефон у такого человека спросим при первом заказе: доставка без
телефона невозможна. Тогда же он может привязать Telegram — по желанию,
не обязательно.

### 2.3 Один человек — один аккаунт

Совпал телефон, почта или Telegram-id — это тот же человек, новый аккаунт
не создаём. В профиле видно, что к чему привязано, и можно добавить
недостающее.

Паролей в проекте нет: их негде хранить безопасно и незачем.

## 3. Уведомления

У человека может быть два канала, и оба работают:

- **Почта** — для тех, кто вошёл через Google или указал адрес.
  Отправка через SMTP: `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`.
- **Telegram** — для тех, кто привязал бота.

Что уходит: заказ принят (с составом и реквизитами Kaspi), заказ
подтверждён, оплата получена, отправлен с трек-номером, доставлен.
Владельцу — каждый новый заказ.

В профиле — переключатели «Письма на почту» и «Сообщения в Telegram».
Если не выбрано ничего, письма всё равно шлём: иначе человек не узнает,
куда платить.

## 4. Роль бота

Бот — служебный, в нём ничего не покупают и не листают:

1. `/start` — приветствие и кнопка «Открыть магазин» (обычная ссылка).
2. `/start c_<ключ>` — просит номер, сверяет, присылает код.
3. Уведомления о заказах тем, кто привязал Telegram.
4. `/id` и `/panel` для владельца.

Всё, что было мастерами, шагами и меню-клавиатурами, удаляется.

## 5. Дизайн-система

Магазин строго монохромный: белый, чёрный, тёмно-серый. Цвет приходит
только от фотографий товара — так вещи выглядят дороже, а интерфейс не
спорит с ними за внимание.

### 5.1 Палитра

```css
:root {
  --bg:            #FFFFFF;   /* фон страницы */
  --surface:       #FAFAFA;   /* карточки, поля ввода */
  --surface-2:     #F2F2F2;   /* нажатое состояние, скелетоны */
  --border:        #EAEAEA;   /* разделители */
  --border-strong: #D4D4D4;   /* рамка активного поля */

  --text:          #0A0A0A;   /* основной */
  --text-2:        #6E6E6E;   /* вторичный: описания, подписи */
  --text-3:        #A1A1A1;   /* третичный: плейсхолдеры */

  --accent:        #111111;   /* кнопки, активные состояния */
  --accent-text:   #FFFFFF;
  --danger:        #D92D20;   /* только ошибки, больше нигде */
}

@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --bg: #0B0B0B;  --surface: #161616;  --surface-2: #1F1F1F;
    --border: #262626;  --border-strong: #3A3A3A;
    --text: #F5F5F5;  --text-2: #A3A3A3;  --text-3: #6E6E6E;
    --accent: #FFFFFF;  --accent-text: #0A0A0A;
  }
}
```

Тёмная тема включается по системной настройке, в шапке — переключатель
на три положения: авто, светлая, тёмная.

### 5.2 Типографика

Системный стек: `-apple-system, "SF Pro Text", "Segoe UI", Inter, Roboto,
sans-serif`. Он уже на устройстве, грузить нечего, сайт выглядит родным.

| Роль | Размер / высота | Начертание | Трекинг |
|---|---|---|---|
| Заголовок страницы | 28 / 34 (десктоп 40 / 46) | 700 | −0.02em |
| Заголовок раздела | 20 / 26 | 600 | −0.01em |
| Название товара | 15 / 20 | 500 | 0 |
| Цена | 17 / 22 | 600 | −0.01em |
| Основной текст | 15 / 22 | 400 | 0 |
| Подпись | 13 / 18 | 400 | 0 |

Цена всегда табличными цифрами (`font-variant-numeric: tabular-nums`) —
иначе колонка цен в корзине пляшет.

### 5.3 Сетка и формы

- Шаг отступов: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64
- Ширина содержимого: максимум 1200, поля 16 на телефоне, 32 на десктопе
- Карточки товара: 2 колонки до 640, 3 до 1024, 4 дальше; промежуток 12
- Фото товара 3:4, скруглено сверху
- Радиусы: 12 — карточка, 10 — кнопка и поле, 999 — чип и аватар
- Тень почти отсутствует: `0 1px 2px rgba(0,0,0,.04)`. Глубина делается
  границей и фоном, а не размытием

## 6. Страницы

```
Знакомство (для нового)  ·  Вход  ·  Код
Главная · Каталог · Товар · Корзина · Оформление · Заказы · Избранное · Профиль
```

**Шапка** — на всех страницах, липкая. Слева логотип, по центру поиск,
справа избранное, корзина со счётчиком, аватар. На телефоне поиск
переезжает под шапку, снизу появляется панель из пяти вкладок.

**Подвал** — разделы каталога, доставка и оплата, контакты, ссылка на
бота. Подвал у сайта обязателен: по нему судят, настоящий магазин или нет.

**Главная.** Баннер, полоса категорий чипами, затем ленты: «Новинки»,
«Заканчивается», «Для дома». Ленты горизонтальные, с инерцией.

**Каталог.** Сетка карточек. На десктопе фильтры колонкой слева, на
телефоне — нижним листом по кнопке «Фильтры». Раздел, размер, цвет, цена
от/до, только в наличии. Внизу листа «Сбросить» и «Показать 128 товаров»,
число живое. Выбранные фильтры попадают в адрес страницы — ссылку с
подборкой можно отправить другу.

**Товар.** Галерея во всю ширину с точками, на десктопе — миниатюры
слева. Название, цена, старая цена зачёркнутая. Размеры плитками, чего
нет — зачёркнуто и не нажимается. Цвета кружками. Описание сворачивается,
характеристики таблицей. Кнопка «В корзину» и сердечко; на телефоне они
липнут к низу экрана.

**Корзина.** Строки с фото, размером, цветом, счётчиком. Свайп влево —
удалить. Итог закреплён: товары, доставка, всего, «Оформить». Пустая
корзина — картинка и кнопка «В каталог», а не пустой экран.

**Оформление.** Один экран, поля друг под другом: имя, телефон, город,
способ доставки, адрес, комментарий. Адрес прошлого заказа подставляется.
Внизу итог и «Подтвердить заказ». Дальше — страница успеха с номером
заказа и реквизитами Kaspi, и то же самое письмом.

**Профиль.** Имя, аватар, «Мои заказы», «Избранное», «Адреса»,
«Уведомления», «Привязать Telegram», «Выйти». У владельца — «Управление».

## 7. Плавность

Плавность — это отсутствие рывков и пустых ожиданий, а не анимации ради
анимаций.

- **Переходы:** 180 мс, `cubic-bezier(0.22, 1, 0.36, 1)`. Страницы
  проявляются, нижние листы поднимаются снизу и тянутся пальцем.
- **Нажатие:** кнопка и карточка на `:active` сжимаются до `scale(0.97)`
  за 80 мс. Самое дешёвое ощущение отзывчивости.
- **Загрузка:** только скелетоны цветом `--surface-2`, никаких спиннеров.
  Скелетон повторяет форму того, что загрузится.
- **Фотографии:** `loading="lazy"`, заданное соотношение сторон, плавное
  проявление за 200 мс. Макет не должен прыгать при загрузке.
- **Корзина:** счётчик меняется мгновенно, запрос уходит следом. Сервер
  отказал — возвращаем как было и показываем сообщение внизу экрана.
- **Списки** длиннее 60 карточек — подгрузка при прокрутке, позиция
  восстанавливается при возврате назад.
- **Клавиатура** работает везде: Tab обходит все элементы, видна рамка
  фокуса, Esc закрывает лист. На сайте это обязательно — люди приходят с
  компьютеров.
- `@media (prefers-reduced-motion: reduce)` выключает все переходы.

## 8. Поиск

Поиск — главный инструмент там, где много товара.

- Липкая строка, скругление 999, фон `--surface`, лупа слева, крестик
  справа при вводе.
- Подсказки с первого символа, запрос уходит через 250 мс после
  последнего нажатия.
- Три группы в подсказках: категории, бренды, товары с миниатюрой.
- Пустой поиск показывает историю и популярные запросы.
- Ничего не найдено — не тупик: «По запросу «джинсы 32» ничего нет» и
  ниже похожие товары.
- Запрос живёт в адресе страницы (`/catalog?q=...`) — результат можно
  переслать ссылкой.

## 9. Ссылки и видимость в поиске

Раз это сайт, а не приложение в мессенджере, добавляется то, чего у
Mini App не было и быть не могло.

- **Адреса человеческие:** `/p/chernoe-plate-1042`, а не `/product?id=1042`.
- **Превью при отправке ссылки:** Open Graph и Twitter Card на каждый
  товар — фото, название, цена. Отправил ссылку в WhatsApp — там видна
  карточка, а не голый адрес.
- **`sitemap.xml` и `robots.txt`** — иначе Google не узнает о товарах.
- **Разметка Schema.org Product** с ценой и наличием — так товар попадает
  в товарную выдачу Google.
- **Скорость:** сжатие изображений в WebP, отдача статики с длинным
  кэшем, `index.html` — без кэша.

Отсюда важное: **если каталог закрыть регистрацией, поисковики его не
увидят вообще**, и ссылка, которой человек поделится, откроется у друга
стеной входа. Для сайта это дорого — вы платите за домен и сервер, а
приходить будет некому. Поэтому предлагаю так: каталог и карточки товара
открыты всем, вход требуется в корзине и при оформлении. Поведение
вынесено в настройку `REQUIRE_AUTH_TO_BROWSE`, по умолчанию `0`. Хотите
строго — ставите `1`, и каталог закрывается сразу. Решение переключается
одной строкой в `.env`, без правки кода.

## 11. Порядок работы

1. Убрать Mini App: `@twa-dev/sdk`, `initData`, хаптика, кнопка меню у
   бота. Переименовать `miniapp/` в `web/`.
2. Токены цвета и типографики — весь интерфейс на новую палитру, старые
   цвета удалить.
3. Шапка, подвал, раскладка под телефон и компьютер.
4. Страница знакомства из трёх блоков.
5. Вход по номеру: заявка, бот, сверка контакта, код, ожидание.
6. Вход через Google.
7. Письма: SMTP, шаблоны, переключатели в профиле.
8. Каталог, карточка товара, фильтры в адресе страницы.
9. Поиск с подсказками.
10. Корзина, оформление, заказы, профиль.
11. Адреса страниц, og-теги, sitemap, Schema.org.
12. Чистка: ни одного упоминания Турции.
13. Админ-панель — отдельным заходом, после всего.

## 12. Админ-панель (следующий этап, набросок)

Отдельный раздел сайта, не отдельное приложение. Сводка (заказы за день,
выручка, что заканчивается), заказы со сменой статуса, товары с быстрым
изменением остатков, добавление товара, покупатели, настройки магазина.
Права по `ADMIN_IDS`, сверяются при каждом запросе. Подробное ТЗ пишем,
когда дойдём.
