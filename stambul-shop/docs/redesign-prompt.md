# Stambul Shop — промт на полное обновление

Документ описывает, каким магазин должен стать. Его можно отдать
разработчику или ИИ целиком: всё, что нужно для работы, здесь.

---

## 0. Рамка: имя и запреты

Название — **Stambul Shop**. Позиционирование: магазин одежды, обуви,
аксессуаров и товаров для дома с доставкой по Казахстану.

**Запрет.** Слова «Турция», «турецкий», «из Турции» не должны встречаться
нигде: интерфейс, описания разделов, тексты бота, письма, README,
og-теги, названия файлов. Проверка — поиск по всему коду не даёт ни одного
совпадения.

Что переписать в первую очередь:
- `SHOP_TAGLINE` в `.env` и `.env.example`
- первая строка `README.md`
- приветствие бота в `backend/app/bot/handlers/start.py`
- `<title>` и `<meta name="description">` в `miniapp/index.html`

Новая подпись магазина: **«Одежда, обувь и всё для дома. Доставка по
Казахстану»**.

## 1. Первый вход: знакомство, потом регистрация

Сейчас человек попадает сразу в каталог и не понимает, куда пришёл.
Новый порядок жёсткий и одинаковый и в Telegram, и в браузере:

```
Три экрана знакомства  →  Регистрация  →  Имя и город  →  Каталог
```

Пройденный онбординг запоминается: `localStorage` до входа, флаг
`onboarding_done` у пользователя — после. Второй раз эти экраны не
показываются никогда.

### 1.1 Три экрана знакомства

Один экран — одна мысль. Крупная картинка сверху (примерно 45% высоты),
заголовок, две строки текста, точки-индикаторы, кнопка внизу.
Переключение — свайпом и кнопкой, обе стороны работают.

| # | Заголовок | Текст | Кнопка |
|---|---|---|---|
| 1 | Всё для себя и для дома | Одежда, обувь, аксессуары, детские вещи, посуда и техника — в одном месте | Далее |
| 2 | Размер и цвет — честно | Показываем только то, что действительно есть на складе. Кончился размер — вы увидите это сразу | Далее |
| 3 | Доставка по Казахстану | Курьером, почтой или самовывозом. Оплата через Kaspi после подтверждения заказа | Начать |

Сверху справа — «Пропустить», ведёт сразу к регистрации. Человек, который
уже всё понял, не должен листать.

### 1.2 Регистрация: три способа

Экран: логотип, строка «Войдите, чтобы сохранять корзину и следить за
заказами», три кнопки одна под другой.

**1. Telegram** — главная кнопка, чёрная, во всю ширину. Видна только
внутри Mini App. Вход мгновенный: `initData` уже содержит имя и id,
подтверждать нечего. Ни кода, ни пароля.

**2. Google** — белая кнопка с рамкой и логотипом G. Основной способ для
браузера. OAuth 2.0, проверка `id_token` по ключам Google на бэкенде,
`GOOGLE_CLIENT_ID` в `.env`. Берём `sub`, `email`, `name`, `picture`.

**3. Номер телефона** — текстовая ссылка «Войти по номеру».

Поток по номеру:
1. Поле с маской `+7 (___) ___-__-__`, кнопка «Получить код».
2. Экран ввода кода: шесть отдельных клеток, автофокус, вставка из буфера
   заполняет все шесть сразу.
3. **Код приходит в Telegram-бот, не по SMS.** Под полем — кнопка
   «Открыть бота», это deep link `t.me/<бот>?start=code_<ключ>`. Человек
   жмёт, бот присылает шесть цифр, человек возвращается и вводит их.
   SMS не нужны: они стоят денег и требуют договора с оператором.
4. Повторная отправка — через 60 секунд, таймер виден.
5. Пять неверных попыток — код сгорает, начинаем заново.

Один аккаунт может иметь и Telegram, и Google, и телефон: если совпал
любой из идентификаторов, это тот же человек, а не новый.

### 1.3 Имя и город

Последний шаг, один экран: имя (подставлено из Telegram или Google, можно
поправить) и город из списка. Кнопка «Пропустить» есть — город спросим
при первом заказе.

### 1.4 Оговорка про закрытый каталог

Требование «сначала регистрация, потом каталог» выполняется, но это
снижает число посетителей: часть людей уходит, не увидев товар. Поэтому
поведение вынесено в настройку `REQUIRE_AUTH_TO_BROWSE` (по умолчанию
`1` — как вы просили). Поставив `0`, вы разрешаете смотреть каталог без
входа, а регистрацию требуете только в корзине. Переключается без правки
кода — можно попробовать оба варианта и сравнить.

## 2. Роль бота

Бот перестаёт быть местом, где что-то делают. Никаких мастеров, шагов и
меню-клавиатур. У него ровно четыре обязанности:

1. `/start` — приветствие и одна кнопка «Открыть магазин».
2. Доставка кодов подтверждения.
3. Уведомления о заказах: покупателю — статус, владельцу — новый заказ.
4. `/id` и `/panel` для владельца.

Всё остальное живёт в приложении.

## 3. Дизайн-система

Магазин строго монохромный: белый, чёрный, тёмно-серый. Цвет в интерфейсе
появляется только от фотографий товара — так одежда выглядит дороже, а
интерфейс не спорит с ней за внимание.

### 3.1 Палитра

```css
:root {
  --bg:            #FFFFFF;   /* фон страницы */
  --surface:       #FAFAFA;   /* карточки, поля ввода */
  --surface-2:     #F2F2F2;   /* нажатое состояние, скелетоны */
  --border:        #EAEAEA;   /* разделители */
  --border-strong: #D4D4D4;   /* рамка активного поля */

  --text:          #0A0A0A;   /* основной */
  --text-2:        #6E6E6E;   /* вторичный: описания, подписи */
  --text-3:        #A1A1A1;   /* третичный: плейсхолдеры */

  --accent:        #111111;   /* кнопки, активные состояния */
  --accent-text:   #FFFFFF;
  --danger:        #D92D20;   /* только ошибки, больше нигде */
}

[data-theme="dark"] {
  --bg: #0B0B0B;  --surface: #161616;  --surface-2: #1F1F1F;
  --border: #262626;  --border-strong: #3A3A3A;
  --text: #F5F5F5;  --text-2: #A3A3A3;  --text-3: #6E6E6E;
  --accent: #FFFFFF;  --accent-text: #0A0A0A;
}
```

Тёмная тема обязательна и включается по системной настройке, а внутри
Telegram — по теме клиента (`themeParams.bg_color`).

### 3.2 Типографика

Шрифт — системный стек: `-apple-system, "SF Pro Text", "Segoe UI", Inter,
Roboto, sans-serif`. Он уже на устройстве, грузить нечего, и интерфейс
выглядит родным.

| Роль | Размер / высота | Начертание | Трекинг |
|---|---|---|---|
| Экранный заголовок | 28 / 34 | 700 | −0.02em |
| Заголовок раздела | 20 / 26 | 600 | −0.01em |
| Название товара | 15 / 20 | 500 | 0 |
| Цена | 17 / 22 | 600 | −0.01em |
| Основной текст | 15 / 22 | 400 | 0 |
| Подпись | 13 / 18 | 400 | 0 |

Цена всегда набирается табличными цифрами (`font-variant-numeric:
tabular-nums`) — иначе колонка цен в корзине «пляшет».

### 3.3 Сетка, скругления, тени

- Шаг отступов: 4 / 8 / 12 / 16 / 24 / 32 / 48
- Поля экрана: 16 по бокам
- Радиусы: 12 — карточка, 10 — кнопка и поле, 999 — чип и аватар
- Тени почти нет: `0 1px 2px rgba(0,0,0,.04)`. Глубина создаётся
  границей и фоном, а не размытием — так интерфейс выглядит чище.
- Карточки товара: две колонки, промежуток 12, фото 3:4, скруглено сверху

## 4. Экраны

```
Онбординг (3)  →  Вход  →  Код / Google  →  Имя и город
                                                  ↓
    Главная · Каталог · Корзина · Избранное · Профиль
```

**Главная.** Строка поиска, полоса категорий чипами, крупный баннер,
затем ленты: «Новинки», «Заканчивается», «Для дома». Ленты горизонтальные,
скролл с инерцией и притормаживанием у края.

**Каталог.** Сетка в две колонки. Сверху липкая панель: поиск, «Фильтры»,
«Сортировка». Фильтры открываются нижним листом, не отдельной страницей:
раздел, размер, цвет, цена от/до, только в наличии. Внизу листа две
кнопки — «Сбросить» и «Показать 128 товаров», число живое.

**Карточка товара.** Галерея фото во всю ширину с точками. Название,
цена, старая цена зачёркнутая. Размеры — плитками; чего нет, то
зачёркнуто и не нажимается. Цвета — кружками. Описание сворачивается.
Характеристики таблицей. Внизу липкая панель: «В корзину» и сердечко.

**Корзина.** Строки с фото, размером, цветом, счётчиком. Свайп влево —
удалить. Внизу закреплён итог: товары, доставка, всего, кнопка
«Оформить». Пустая корзина — не пустой экран, а картинка и кнопка
«В каталог».

**Оформление.** Один экран, поля друг под другом, без шагов: имя,
телефон, город, способ доставки, адрес, комментарий. Адрес прошлого
заказа подставляется. Внизу — итог и «Подтвердить заказ». После —
экран успеха с номером заказа и реквизитами Kaspi.

**Профиль.** Имя, аватар, «Мои заказы», «Избранное», «Адреса»,
«Поддержка», «Выйти». У владельца — шестой пункт «Управление».

## 5. Плавность

«Плавно» — это не анимации ради анимаций, а отсутствие рывков и пустых
ожиданий.

- **Переходы:** 180 мс, `cubic-bezier(0.22, 1, 0.36, 1)`. Экран вперёд
  въезжает справа, назад — уезжает вправо. Нижние листы поднимаются
  снизу и тянутся пальцем.
- **Нажатие:** любая кнопка и карточка на `:active` сжимается до
  `scale(0.97)` за 80 мс. Это самое дешёвое ощущение отзывчивости.
- **Загрузка:** только скелетоны в цвете `--surface-2`, никаких
  крутящихся спиннеров. Скелетон повторяет форму того, что загрузится.
- **Фотографии:** `loading="lazy"`, фиксированное соотношение сторон,
  плавное проявление за 200 мс. Макет не должен прыгать при загрузке.
- **Корзина:** счётчик меняется мгновенно, запрос уходит следом. Если
  сервер отказал — возвращаем как было и показываем короткое сообщение
  внизу экрана.
- **Хаптика** в Telegram: лёгкая — на выбор размера и добавление в
  корзину, средняя — на оформление заказа
  (`WebApp.HapticFeedback.impactOccurred`).
- **Списки** длиннее 60 карточек — подгрузка по мере прокрутки, позиция
  восстанавливается при возврате назад.
- `@media (prefers-reduced-motion: reduce)` выключает все переходы.

## 6. Поиск

Поиск — главный инструмент в магазине, где много товара.

- Липкая строка сверху, скругление 999, фон `--surface`, иконка лупы
  слева, крестик справа при вводе.
- Подсказки появляются с первого символа, запрос уходит через 250 мс
  после последнего нажатия.
- В подсказках три группы: категории, бренды, товары с миниатюрой.
- Пустой поиск показывает историю запросов и популярное.
- Ничего не найдено — не тупик: «По запросу «джинсы 32» ничего нет» и
  ниже похожие товары.

Ограничение: не больше 5 запросов кода на номер в час.

## 8. Порядок работы

1. Токены дизайна и типографика — весь интерфейс переезжает на новую
   палитру, старые цвета удаляются.
2. Онбординг: три экрана, свайп, запоминание.
3. Вход через Telegram и через номер с кодом от бота.
4. Вход через Google.
5. Охранник маршрутов и настройка `REQUIRE_AUTH_TO_BROWSE`.
6. Переделка экранов под новую сетку: главная, каталог, карточка.
7. Поиск с подсказками.
8. Корзина, оформление, профиль.
9. Чистка: ни одного упоминания Турции нигде.
10. Админ-панель — отдельным заходом, после всего.

## 9. Админ-панель (следующий этап, набросок)

Отдельный раздел приложения, не отдельное приложение. Разделы: сводка
(заказы за день, выручка, что заканчивается), заказы со сменой статуса,
товары с быстрым редактированием остатков, добавление товара, покупатели,
настройки магазина. Права — по `ADMIN_IDS`, сверяются при каждом запросе.
Подробное ТЗ пишем, когда дойдём.
